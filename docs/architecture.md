# Границы первой версии

Минимальная система — macOS 14; значение согласовано в SwiftPM и метаданных пакета приложения. На Apple Silicon подключены загрузка, управление и проверка локальных моделей, фоновая индексация, смысловой поиск и [чат по истории](chat.md).

`BufferaCore` содержит сериализуемый контракт содержимого, SQLite, общее декодирование текста `ClipboardText` и разрешение `MCPAccess`. Каждый экземпляр `HistoryStore` принадлежит одной последовательной очереди или actor; все SQL-параметры связаны через prepared statements. Отдельная таблица payloads не загружается при поиске. Транзакция включает вставку, дедупликацию и применение лимитов. Уникальный хеш учитывает границы элементов, типы и бинарные данные. Идентификаторы не переиспользуются, в том числе для имён экспорта.

Схема версии 10 содержит признаки `is_concealed`, `is_favorite`, таблицу `clip_ocr`, `clips.is_remote INTEGER NOT NULL DEFAULT 0 CHECK(is_remote IN (0,1))`, отдельные таблицы смыслового индекса и состояния очистки секретов. Миграции версий 0–9 выполняются в одной `BEGIN IMMEDIATE` с rollback при ошибке. Старым записям не приписывается удалённое происхождение: 0 означает отсутствие сохранённого признака. Существующие id, payload, избранное и результаты OCR не пересоздаются. Версия 10 добавляет `clips.label TEXT NOT NULL DEFAULT ''`: пользовательскую подпись избранного, отдельную от содержимого и открыто хранимую даже для скрытых записей. `HistoryStore+Labels.swift` проверяет длину и признак избранного при записи; снятие звезды сохраняет подпись. При объединении скрытых дублей сохраняется подпись выжившей записи, а при её отсутствии — подпись удаляемого дубля. Подписи не входят в поисковый индекс, MCP и контекст чата. Более новая неизвестная версия отклоняется без понижения.

`clips.sort_date` отделяет порядок использования от даты копирования `date`: миграция заполняет его прежней датой и создаёт индекс сортировки. Вставка и дедупликация обновляют обе даты. `markUsed(id:date:)` меняет только `sort_date`, без payload, источника, признаков и OCR; отсутствие записи возвращает `HistoryError.missing`. Поиск и очистка лимитов используют `sort_date DESC, id DESC`, календарный фильтр и очередь OCR — прежнюю дату копирования.

`HistoryStore.nearby(anchorID:before:after:)` читает актуальную опору по id и ближайшие строки по `(date,id)` на той же последовательной очереди. По умолчанию возвращается до 10 более ранних и 10 более поздних записей вместе с опорой, в порядке `date DESC,id DESC`; одинаковые даты разделяются по id. Каждая сторона ограничена 0–100 записями. Запросы используют существующий индекс `clips_date` и общий декодер `ClipSummary`, не загружают payload или OCR и не принимают поисковых фильтров. Отсутствующая опора возвращает `HistoryError.missing`. Отдельного журнала копирований нет, повторный захват заменяет прежнюю дату и источник. Выбор через Buffera хронологию соседей не меняет.

`HistoryStore.setFavorite(id:isFavorite:)` атомарно устанавливает точный флаг, допускает повторную установку того же значения и возвращает `HistoryError.missing` для отсутствующего id. Дедупликация и ручное скрытие не меняют избранное. Общий предикат `search`/`count` комбинирует `SearchFilter.favoritesOnly` с остальными условиями. Оконные функции автоматической очистки считают позиции и сумму bytes только среди `is_favorite=0`: избранное находится вне лимитов. Снятие флага не запускает очистку; обычные лимиты применяются при следующей вставке. Явный `delete` по-прежнему удаляет запись вместе с payload.

`ClipboardService` работает с AppKit на главном потоке. Данные копируются из NSPasteboardItem до передачи на очередь хранения. После чтения сверяется changeCount; устаревший снимок отбрасывается. Восстановление создаёт новые NSPasteboardItem и обновляет lastChange, чтобы избежать петли захвата.

`com.apple.is-remote-clipboard` сохраняется как отдельный `isRemote` до удаления служебных представлений из payload. Для удалённой записи source остаётся пустым; карточка показывает «С другого устройства». Идентификатор устройства из этого маркера недоступен. Для местной записи источник берётся из `org.nspasteboard.source`; явное пустое/неизвестное значение не заменяется активным приложением. Только при отсутствии маркера используется имя активного приложения, кроме loginwindow и WindowServer. При дедупликации source, isRemote и дата соответствуют последнему копированию. `sources()` исключает удалённые записи, UI также скрывает собственное приложение и системные процессы. Общий предикат search/count поддерживает `remoteOnly` и `concealedOnly`. В UI `HistoryContentType` задаёт один выбранный тип: обычный ClipKind, «С устройств» или «Скрытые». Сайдбар и подменю «Тип» используют один список вариантов и один обработчик выбора; новый тип заменяет прежний и преобразуется в соответствующие поля SearchFilter. Тип не меняет дату, приложение, раздел истории/избранного и сохраняется до сброса или перезапуска.

`ClipboardSessionMonitor` проверяет снимок `CGSessionCopyCurrentDictionary` и наблюдает отдельные уведомления блокировки, смены активного сеанса и сна. `CGSSessionScreenIsLocked` и имена distributed-уведомлений не являются документированным контрактом Apple; механизм изолирован в мониторе. При недоступном снимке захват запрещён. `ClipboardService.poll()` проверяет разрешение до и после чтения, а каждый переход сеанса обновляет changeCount без чтения содержимого. Так пропускаются изменения во время блокировки, включая цикл блокировка/разблокировка между опросами. Ручная пауза независима. Уже принятые до блокировки записи могут завершить запись на последовательной очереди. Universal Clipboard, доставленный только после возвращения в сеанс, не содержит времени исходного копирования, поэтому отличить такой случай от нового копирования нельзя.

`SecretHistoryMode` хранится в UserDefaults, по умолчанию `skip`. `ClipboardService.savesConcealed` применяется перед запросом данных представлений: маркеры `ConcealedType` / `com.agilebits.onepassword` либо пропускают всю группу, либо передают её в канонический `HistoryStore.insert`. Конфиденциальный маркер имеет приоритет над transient/auto-generated; обычные временные записи пропускаются. Настройка действует на новые захваты, не удаляет уже сохранённые секреты. Явная команда «Скрыть» шифрует существующий payload в обоих режимах.

Шифрование введено в схеме 8: `payloads.encoding` (`0` — прежний binary plist, `1` — AES-GCM combined) и `secret_storage` с идентификатором ключа. Схема 9 переносит задания очистки в отдельную singleton-таблицу `secret_maintenance` с флагами `needs_checkpoint` и `needs_vacuum`; прежний `secret_storage.needs_cleanup` больше не используется. Основной процесс передаёт `SecretPayloadCipher` с `KeychainSecretKeyProvider`; фоновые индексаторы и MCP открывают store без провайдера. Случайный master key — 256 бит; HKDF-SHA256 выводит отдельные ключи AES-256-GCM и HMAC-SHA256. Новый nonce генерирует CryptoKit. AAD связывает версию формата и защищённый fingerprint, поэтому перестановка ciphertext между разными записями не проходит аутентификацию. Обычные payload и SHA-256 fingerprint остаются прежними; секреты используют HMAC fingerprint, чтобы база не содержала проверяемый без ключа хеш пароля.

`KeychainSecretKeyProvider` использует file-based macOS Keychain с ACL только основного приложения; ключ кэшируется в памяти процесса. Отказ блокирует повторные некэшированные обращения, включая создание ключа с новым UUID, до явного действия с секретом: показа, восстановления, перетаскивания, скрытия или включения шифрованного режима. Обычные захваты и действия с открытыми записями этот отказ не сбрасывают. Современные access groups потребовали бы provisioning/signing, которых текущая ad-hoc сборка не имеет. macOS может запросить разрешение после смены подписи. При отсутствии существующего ключа, отказе в доступе или повреждённом ciphertext открытого fallback для секретной записи нет. Потерянный ключ или идентификатор при наличии ciphertext не заменяется новым автоматически. При недоступном ключе обычные захваты продолжаются; сопоставление с ранее скрытым payload по HMAC в этом случае невозможно, поэтому только маркер источника гарантирует распознавание новой копии как секрета. Такой fallback разрешён только для `keyUnavailable`: ошибки SQLite прерывают вставку.

Доступ к Keychain и подготовка ключей выполняются до `BEGIN IMMEDIATE`; транзакция повторно проверяет идентификатор и использует неизменяемый `PreparedKey` без обращений к внешнему провайдеру. Новый идентификатор регистрируется в той же транзакции, что и секрет. При rollback в Keychain может остаться неиспользуемый ключ, но существующий ключ не заменяется. Чтение payload и признака секретности завершается до расшифровки, поэтому запрос разрешения Keychain не удерживает снимок SQLite.

`insert` атомарно обновляет маску, шифротекст, fingerprint, индексы и лимиты. Повторы сохраняют скрытие и избранное при доступном ключе. `conceal` использует тот же шифратор и удаляет OCR/embeddings в транзакции. `restorablePayload` добавляет `ConcealedType`, если его не было у вручную скрытой записи. Заголовок, текст и search содержат только безопасную маску и source; дата, тип, source и размер остаются открытыми. Поиск по содержимому секретов не выполняется.

При запуске на очереди истории `protectLegacySecrets` шифрует старые concealed payload одной транзакцией. При ошибке исходные записи не удаляются, но чтение legacy concealed plaintext запрещено. Ошибка показывается пользователю; включение шифрованного режима повторяет попытку. После успешного `COMMIT` вставка и скрытие возвращают успех независимо от обслуживания базы: очистка не задерживает обновление панели и инвалидацию чата.

`secure_delete=ON` удаляет содержимое освобождаемых страниц; обычное скрытие атомарно ставит только `needs_checkpoint`. `performSecretMaintenance` выполняет checkpoint/TRUNCATE при запуске и затем раз в 30 секунд на той же очереди истории. Для очистки установлен нулевой busy timeout: занятый читатель оставляет флаг для следующей попытки, а ошибка пишется в лог без модального окна. Старые базы версий 1–8 получают отдельное разовое задание `needs_vacuum`, даже если строки ключа ещё нет; миграция legacy plaintext также требует его. Это очищает старые свободные страницы, оставшиеся до включения `secure_delete`. Новая база и обычные скрытия полного `VACUUM` не требуют. Успешный `VACUUM` снимает только свой флаг; если финальный checkpoint занят, повторяется только checkpoint. Сам legacy `VACUUM` может временно занять очередь и блокировку записи SQLite. Флаги переживают перезапуск; предыдущие бэкапы/снимки файловой системы не очищаются.

Ручной `conceal(id:)` шифрует payload, заменяет fingerprint, маскирует metadata и удаляет OCR/embeddings в одной транзакции. В UI «Скрыть» доступно для обычного текста и ссылок. «Показать» декодирует текст по явному действию и хранит не более 4000 символов только в состоянии панели; отдельный `revealToken`, выбранный id и видимость окна отсеивают поздний ответ. Смена выбора, обновление списка или закрытие сбрасывают раскрытие. В просмотре раскрытого секрета выделение текста отключено, чтобы стандартный `NSTextView` не экспортировал его без маркера; Enter по-прежнему восстанавливает полный payload через `restorablePayload`. Обычный текст в просмотре можно выделять и копировать. Скрытые записи не создают миниатюры или подсказки с содержимым, доступное описание до раскрытия — «Скрытая запись». Временный показ не меняет флаг в SQLite.

`HotKeys` владеет регистрациями и обработчиком на `GetEventDispatcherTarget()`. V глобальна, C регистрируется только при открытом окне. Проверяются signature и id событий нажатия/отпускания; уже зажатые id позволяют отсеять автоматический повтор. Регистрация V идемпотентна; после конфликта её можно повторить из меню, также она повторяется при завершении другого приложения. Повторное нажатие перед завершением активации направляется в уже видимую панель и не перезапускает загрузку.

`HistoryShortcutGesture` считает отдельные нажатия в пределах начального удержания `⌘⌥`, которым открыта панель. Одно нажатие с отпусканием оставляет окно в обычном режиме до следующего открытия; последующие V/C только двигают выбор. Второе нажатие без отпускания начального удержания включает выбор при отпускании любого обязательного модификатора. Жест запускается только в `open(fromShortcut: true)`, а `HistoryPanel.shortcutPressed` продолжает его лишь пока он активен; Carbon и прямые оконные события используют этот общий путь. `flagsChanged` дополняется опросом `NSEvent.modifierFlags` каждые 25 мс только во время начального жеста, чтобы заметить отпускание до получения окном фокуса; дополнительных разрешений не требуется. Отпускание после перебора вызывает обычный `confirm()`, включая ожидание первой загрузки. Закрытие, ошибка и подтверждение сбрасывают жест и таймер; открытие через меню остаётся обычным, а Escape отменяет отложенный выбор.

`HistoryPanel` управляет выбором в окне, которое остаётся открытым после вызова. Enter или двойной щелчок фиксируют id выбранной записи; подтверждение до завершения первой загрузки откладывается до её результата. На время подтверждения выбор, поиск и фильтры заблокированы. `PickerWindow.sendEvent` обрабатывает клавиши панели до поля поиска, а делегат поля дополнительно обрабатывает команду Enter. `AppDelegate` читает payload зафиксированного id, восстанавливает системный буфер и только после успеха ставит `markUsed` на ту же последовательную очередь перед закрытием окна. Следующий запрос видит новый порядок. Ошибка изменения порядка показывается через существующий статус ошибок без повторного копирования. Окно закрывается с возвратом фокуса предыдущему приложению.

При вводе поиска, смене фильтров и повторном открытии `HistoryPanel.refresh(retainingCards: true)` сохраняет прежние карточки и миниатюры до готовности нового результата. Это только визуальный снимок: действия над ним отключены, стрелки и Enter применяются к пришедшему результату. Первая страница заменяет список целиком без промежуточной очистки; пустой результат и ошибка убирают старые карточки. Если при открытии, в том числе по хоткею, снимка ещё нет, окно показывается после загрузки и раскладки карточек. Повторные нажатия хоткея в это время сохраняются, внешний клик или переключение приложения отменяют ожидающий показ незакреплённой панели. Скрытие, удаление и прочие изменения содержимого используют обычный `refresh` с очисткой; подтверждённое скрытие/удаление инвалидирует снимок и при закрытой панели. Проверки: `Tests/HistoryPanelChecks/LoadingPresentationChecks.swift`.

Поисковые ответы защищены номером `searchGeneration`, загрузки содержимого — `generation`, а подтверждение — отдельным `confirmationToken`: поисковое обновление не отменяет уже выбранную запись. Escape, закрытие и повторное открытие инвалидируют ожидающее подтверждение, поэтому позднее чтение payload не меняет буфер после отмены. Потеря фокуса также закрывает окно; календарный поповер, просмотр, настройки внешнего вида, контекстное меню карточки и NSSavePanel временно могут владеть ключевым статусом без отмены сессии.

Окно — обычная активирующаяся `NSPanel` с `hidesOnDeactivate=false`. Глобальный вызов активирует Buffera, делает панель ключевой и переводит фокус в список; после асинхронной активации фокус назначается повторно. Начало печати из списка создаёт новый запрос и переводит фокус в поиск; `⌘F` позволяет редактировать существующий запрос. Решение «переместить выбор или открыть панель» учитывает видимость, ключевой статус и дочерние взаимодействия. Системный Logger с subsystem `local.buffera.app` записывает только регистрацию клавиш, жизненный цикл панели и результат подтверждения, без содержимого буфера.

Запрос, `HistoryFilters` и раздел «История»/«Избранное» остаются в памяти `HistoryPanel` между закрытиями окна; `open()` сохраняет эти значения до истечения срока из `HistoryResetPreferences` (`historyReset.enabled`, `historyReset.minutes`; по умолчанию включено, 1 минута, диапазон 1–1440 минут). `close()` запоминает время только для видимого окна; повторное закрытие скрытого окна не продлевает срок. При следующем `open()` после истечения срока общий с ручным сбросом путь очищает запрос, фильтры, раздел, сохранённый выбор и подсказку нового копирования, после чего запрашивает первую страницу. Раннее открытие отменяет отсчёт; пока окно открыто, сброса нет. Настройки из `HistoryResetSettingsView` читаются заново при каждом открытии, отдельного таймера нет. В UserDefaults они не записываются и после перезапуска приложения начинаются заново. Кнопка «Вся история» и `⌘0` явно очищают запрос, фильтры и раздел. Повторные клавиши навигации во время первой загрузки накапливаются в знаковом `pendingMoveDelta` и применяются к восстановленному выбору. Это состояние отделено от постоянных настроек внешнего вида.

Для временного просмотра соседей `NearbyHistoryState` сохраняет строки исходного поиска, счётчик, выбранный id и позицию прокрутки. Поисковые контролы остаются с прежними значениями, но блокируются; обычная пагинация и обновления OCR не подменяют соседей. `requestNearby` проходит через `AppDelegate` на общую очередь хранения. Отдельный `nearbyToken`, id опоры и видимость окна отсеивают устаревшие ответы и ошибки; `onNavigate` инвалидирует прежние запросы поиска, содержимого и подтверждения. Вход отменяет просмотр и временное раскрытие секрета. Карточки, миниатюры, действия и подтверждение используются существующие, опора получает отдельную метку, независимую от выбора. Смена опоры сохраняет первоначальную точку возврата.

Копирования и изменения OCR отмечают сохранённый поиск как требующий обновления, не переставляя текущих соседей. Изменение избранного отмечает его до асинхронной записи; скрытие и удаление перезапрашивают соседей после завершения. При возврате после изменений панель запрашивает свежие строки, сохраняет исходный выбор и прокрутку и не рисует старый снимок. Закрытие завершает временный режим и также не восстанавливает устаревшие карточки на время анимации; следующий `open()` загружает исходный поиск. При отсутствии изменений возврат использует сохранённые строки. Escape сначала закрывает просмотр, затем возвращает поиск; ошибка или удаление опоры оставляет доступным возврат.

После `insert` панель получает id внешнего копирования. `captureSelectionToken` присваивается на главном потоке при захвате и меняется после успешного восстановления: запоздалое уведомление о более раннем копировании не возвращает старый выбор. Он имеет приоритет при следующей загрузке, только если запись есть в текущих результатах; неподходящее копирование не сбрасывает фильтры и прежнее выделение. Успешное подтверждение завершает этот приоритет. Esc и уход фокуса сохраняют выбор, в том числе если список ещё загружается. Повторное открытие запрашивает ранее загруженную глубину; при необходимости запрос расширяется до сохранённого id. Отложенное закрытие по потере фокуса защищено `presentationToken`, а жест быстрого выбора отменяется сразу при настоящем уходе фокуса.

После успешного `setFavorite` callback передаёт подтверждённый флаг и id. Панель обновляет текущую запись и кнопку звезды на месте, без очистки списка или пересоздания всех карточек. В разделе избранного снятая запись удаляется точечно; сохраняется существующий выбор либо выбирается ближайший сосед. `pendingFavorites` блокирует повторный запрос для того же id и новую пагинацию избранного до завершения изменений, чтобы удаление не сдвинуло ожидаемый offset. Ошибка снимает блокировку и показывает сообщение, не сбрасывая состояние всей панели.

`HistoryFilters` владеет одним состоянием типа, даты и приложения. В боковом меню сверху расположены типы, затем период и приложения. Компактная кнопка фильтров рядом с поиском открывает нативное меню типа, даты, приложения и сброса; оно доступно и при скрытии сайдбара кнопкой или `⌘⌥S`. Отдельной строки фильтров над карточками нет. Переключение представления фильтры не сбрасывает. Дата остаётся поповером с быстрыми периодами «Всё время», «Сегодня», «Вчера», «7 дней», «30 дней» и двумя `NSDatePicker` в режиме календаря. Границы приводятся к локальным началам дней, порядок нормализуется, верхняя граница SQL равна началу дня после выбранной даты. Поэтому пользовательский конец периода включён целиком; 7/30 дней включают сегодня.

Окно `.resizable` использует `NSVisualEffectView` с материалом `.popover` и смешиванием `.behindWindow`. Стандартные кнопки закрытия, сворачивания и разворачивания скрыты. `HistoryAppearance` сохраняет в отдельных ключах `historyAppearance.*` режим `.floating/.left/.right`, 1–4 колонки, 3–12 видимых строк и видимость бокового меню. Неверные типы получают значения по умолчанию, числовые значения ограничиваются допустимыми границами. `SettingsWindow` — отдельное сохраняемое окно, доступное через шестерёнку, `⌘,` и меню приложения. Оно сохраняет настройки сразу и передаёт компоновку панели через callback; `HistoryLimits` обслуживает настройки хранения и захват. Геометрия истории меняется без её показа и перехвата фокуса.

Положение и размер обычного окна сохраняются под именем `BufferaHistory`; ширина боковой панели без меню — отдельно в `historyAppearance.sideWidth`. Переход в боковой режим не перезаписывает обычную геометрию. Боковая панель располагается у выбранного края видимой области экрана под указателем, занимает доступную высоту и учитывает число колонок, ширину меню и границы экрана. При открытии панель сразу показывается в конечной позиции, без анимации. При закрытии она сдвигается за край; `presentationToken` отменяет устаревшие шаги анимации, в том числе при повторном открытии, а `isClosing` блокирует ввод во время закрытия. Системный Reduce Motion отключает анимацию закрытия. Перед показом обычного окна его рамка проверяется относительно текущих экранов и возвращается в видимую область при необходимости.

`HistoryCardsView` владеет `NSCollectionView`, повторно используемыми ячейками, прокруткой и раскладкой; записи и действия остаются в `HistoryPanel`. `HistoryCardsMetrics` рассчитывает фактическое число колонок по доступной ширине: минимум ширины — 230 точек, промежуток — 8. Число видимых строк задаёт высоту обычных карточек (минимум 96 точек) и ограничивает высоту текста в боковых панелях. В панелях `NSCollectionViewDelegateFlowLayout` запрашивает высоту по содержимому; `ClipCardView` измеряет тот же текст и шрифт, что показывает, с учётом ширины и места под действия. Короткая запись занимает от 74 точек, картинка — от 106; скрытая запись измеряется по точкам, без доступа к длине секрета. Карточки одной строки сетки получают максимальную высоту в этой строке. Кеш измерений сбрасывается при изменении ширины, плотности, режима или данных; пагинация сохраняет измерения старых записей. Изменение размера окна перестраивает раскладку, загрузка страницы добавляет элементы, а изменение избранного обновляет или удаляет отдельную ячейку без мерцания всего списка. В сетке `↑/↓` смещают выбор на фактическое число колонок, `←/→` — на одну запись; глобальные `⌘⌥V/C` всегда перебирают линейную последовательность. `Tab` переводит фокус между карточками и поиском.

`ClipCardView` отвечает только за представление записи и callbacks. Кнопки допустимых для записи действий постоянно видны внутри карточки, выбранная карточка имеет обводку. `ClipCardAction` задаёт названия, символы, доступность и подсказки сочетаний для кнопок и контекстного меню: Enter — копирование, пробел/`⌘Y` — просмотр, `⌘D` — избранное, `⇧⌘N` — соседи, `⇧⌘C` — скопировать иначе, `⇧⌘H` — скрытие/показ, `⇧⌘R` — Finder, `⇧⌘S` — сохранение, `⌘⌫` — удаление. Удаление доступно через контекстное меню и клавиатуру; экспорт — только для нескрытых картинок. Кнопки, меню и клавиатура передают действие в `HistoryPanel.perform`, который фиксирует id и вызывает существующие операции `AppDelegate`. Нажатие действия не прокручивает карточку принудительно. Удержание Command показывает метки `⌘1`–`⌘9` у первых девяти результатов; сочетание сразу подтверждает соответствующую запись.

`ClipPreview` показывает временный `NSPopover`, не создавая экспортный файл. Payload читается и декодируется на очереди истории: текст ограничен 500 000 символов для просмотра, изображение уменьшается ImageIO до 1600 пикселей, для файлов показываются пути, для прочих данных — перечень форматов. Панель проверяет поколение запроса, отдельный `previewToken`, видимость и выбранный id перед показом. Смена выбора, обновление и закрытие отменяют предыдущий просмотр. Пробел открывает его только вне редактирования поиска; `⌘Y` работает также из поля поиска. В просмотре пробел/Escape закрывают поповер, Enter подтверждает запись, стрелки закрывают просмотр и перемещают выбор. Закрытие освобождает контроллер с декодированным содержимым. Скрытый payload не декодируется этим путём: сначала требуется явный показ, после которого просмотр использует уже раскрытые 4000 символов.

Миниатюры загружаются через `requestThumbnail`: payload читается и передаётся ImageIO на очереди истории, а результат возвращается с проверкой поколения запроса. ImageIO уменьшает PNG/TIFF до 320 пикселей для высоких карточек и Retina; панель кеширует до 150 миниатюр. Замыкание удерживает конкретную ячейку слабо, поэтому поздний ответ не меняет другую строку. Повреждённое изображение оставляет значок типа; исходный payload и путь экспорта не меняются.

`TextTransformation` в ядре содержит чистые преобразования текста и их русские названия/описания. JSON разбирается по грамматике и форматируется с сохранением исходных лексем строк, чисел и ключей; ограничения входа, результата и глубины проверяются до возврата. Очистка URL фильтрует исходные сегменты query, не пересобирая нетронутые компоненты через URLComponents.

`CopyTransformOperation` определяет доступные действия для нескрытых text/link/image. `CopyTransformService` читает актуальные `summary(id:)`, payload и готовый `imageText(id:)` на общей очереди SQLite. Декодирование через общий per-item метод `ClipboardService.text(in:)`, преобразование и OCR выполняются на отдельной последовательной очереди. Для преобразований каждый item должен иметь читаемый текст: частичный результат не допускается. Готовый OCR переиспользуется, при отсутствии запускается существующий `ImageTextRecognizer`. После обработки сервис повторно проверяет существование и доступность записи. Изменений схемы нет.

`CopyTransformMenu` используется как подменю карточки и как отдельное меню кнопки/сочетания клавиш. Панель заранее запрашивает варианты только для выбранной записи. `CopyTransformService.operations` проверяет полный текст теми же преобразованиями, которые используются при копировании; действия без изменений и неподходящие варианты исключаются. Для строк дополнительно требуется реальная склейка соседних строк или точный повтор непустой строки. OCR при открытии меню не запускается; известный пустой или ограниченный результат исключает действие. Ответ доставляется в common/eventTracking-режимах главного RunLoop и обновляет уже открытое меню. Поколения запросов отсекают ответы для прежнего выбора.

Выбор пункта сразу запускает преобразование и копирование. Панель фиксирует ID источника, инвалидирует незавершённый поиск и блокирует новые действия на время обработки. Захват и OCR отмечают историю для обновления после ошибки или отмены. Esc отменяет ожидающее копирование и оставляет историю открытой; закрытие окна также инвалидирует токены. Перед записью `AppDelegate` снова проверяет источник на очереди хранения и актуальность операции, затем использует общий с обычным выбором `restoreClipboard`: `ClipboardService.restore` → подавление собственного захвата → `markUsed`. В буфер записывается только полный UTF-8 текст; payload исходника не переписывается.

`TemporaryImageExports` создаёт файлы для Finder в системной временной папке `local.buffera.app/ImageExports`. Запись атомарная, каталог имеет режим 0700, файлы — 0600. Повторный экспорт id заменяет файл и обновляет время. Очистка выполняется при запуске, каждый час и перед/после экспорта: файлы старше 24 часов удаляются, затем самые старые удаляются до лимита 256 МиБ. Текущий экспорт защищён от очистки; отдельный файл больше лимита отклоняется. Обрабатываются только обычные файлы собственного шаблона имён без символических или жёстких ссылок; доступ к кешу защищён lock.

«Сохранить как…» пишет PNG в выбранный NSSavePanel путь, обходя временный кеш. Скопированный пользователем в другую папку файл становится независимой копией и не участвует в очистке. Ни исходный payload истории, ни постоянные файлы, ни прежняя папка `Application Support/Buffera/Exports` временной очисткой не затрагиваются.

## Эмбеддинги и гибридный поиск

`BufferaModels` управляет весами и предоставляет `EmbeddingRuntime`, общий адаптер к `BufferaEmbeddingWorker` на llama.cpp. Рабочий процесс получает текст через pipe и возвращает нормализованные векторы размерности 768; сетевого сервера нет. Текст не передаётся через командную строку. `LocalModelReadAccess` позволяет UI и MCP проверять сохранённый выбор модели и готовность файлов без создания второго загрузчика. Worker освобождает память после 60 секунд простоя; выключение модели отменяет текущую обработку.

`BufferaSearch.EmbeddingIndexer` владеет отдельным соединением `HistoryStore` внутри actor. Транзакция базы не удерживается во время вычисления векторов. В схеме 7 `embedding_index` хранит fingerprint модели, размерность и версию подготовки входа, `clip_embedding_jobs` — устойчивую очередь `pending`/`complete`/`failed`, `clip_embedding_chunks` — векторы фрагментов. Первое включение или смена fingerprint атомарно создаёт очередь через `INSERT … SELECT`. Начальная очередь выбирается только по метаданным, без чтения текста; пустые записи отсеиваются при получении задания. Ограничение текста и SHA-256 вычисляются для одной записи за раз, чтобы не читать и не хешировать всю историю внутри транзакции перестройки.

Вход состоит из `clips.text` для видимых text/link/file и завершённого `clip_ocr.text` для image. Источник, даты, избранное и заголовок не дублируются в embedding-входе. Повторное копирование того же содержимого сохраняет векторы; OCR ставит запись в очередь после успешного завершения. Политика входа ограничивает его 128 КиБ UTF-8 без разрыва кодовой точки. Worker токенизирует текст и создаёт фрагменты по 512 токенов с перекрытием 64, до 32 фрагментов на запись. Усечение отмечается в прогрессе, исходный payload не меняется. Разные префиксы запросов и документов, версия модели, SHA-256 и правила фрагментации входят в ключ совместимости.

Завершение задания проверяет модель и fingerprint содержимого, наличие записи, её видимость и состояние `pending`. Повторный или запоздалый результат не восстанавливает удалённые либо скрытые данные. Внешние ключи удаляют задания и фрагменты при явном удалении и очистке по лимитам. Скрытие удаляет их в той же транзакции, что и OCR. Неудачная обработка остаётся в очереди для явного повтора; выключение сохраняет индекс, завершение приложения оставляет незаконченное задание `pending`.

`sqlite-vec` 0.1.9 включён статически из официальной amalgamation-сборки с проверенной контрольной суммой; исходники, обе лицензии MIT/Apache-2.0 и происхождение сохранены в `Sources/CSQLiteVec`. Тонкая C-обёртка включает NEON только на поддерживаемых ARM-целях. Используются обычные таблицы с внешними ключами и готовая функция `vec_distance_cosine`: это сохраняет единый предикат фильтров и не требует копировать метаданные в `vec0`. Поиск перебирает подходящие векторы; это линейная стоимость относительно числа фрагментов, а не ANN-индекс.

`HistoryStore.hybridSearch` в одном read snapshot получает все точные совпадения в прежнем порядке `sort_date DESC,id DESC`, затем до 200 смысловых кандидатов с cosine similarity не ниже 0,70. У записи с несколькими фрагментами берётся минимальное расстояние. Порог выбран на небольшом наборе русских, английских и кодовых примеров и остаётся эвристикой, а не гарантией качества на любой истории. Семантические совпадения сортируются по расстоянию, затем времени использования и id; уже найденные точно записи не дублируются. Все существующие фильтры применяются до ограничения кандидатов. Скрытые записи допускаются только в обычной части поиска по безопасным метаданным.

`HybridSearchService` используется UI и MCP. Он вычисляет вектор запроса, перепроверяет доступность модели после ожидания, затем открывает read-only соединение для поиска. Без готового совместимого индекса или при ошибке модели возвращается обычный поиск с причиной перехода. В UI включённый флажок «Искать также по смыслу» выбирает `automatic`, выключенный — `literal`. Пустой запрос и режим `literal` не запускают модель. Для продолжения страницы сохраняется порядок смысловых кандидатов; каждая страница повторно проверяет видимость и фильтры, поэтому растущий индекс не вставляет новые смысловые результаты в середину текущей пагинации. Новый запрос первой страницы обновляет набор кандидатов.

## MCP через stdio

`BufferaMCP` — отдельный executable в `Contents/MacOS` пакета приложения. Он не запускает `AppDelegate`, окно, захват буфера или OCR. Агент запускает процесс с stdin/stdout; helper читает уже существующую локальную историю и может работать без запущенного GUI. `scripts/build-app.sh` собирает оба executable, подписывает helper, затем пакет приложения. Официальный `modelcontextprotocol/swift-sdk` закреплён на `0.12.1`, транзитивные версии — в `Package.resolved`. Текущий граф зависимостей требует Swift 6.4 для сборки; runtime остаётся macOS 14.

`BufferaMCPKit` отделяет протокол от приложения. `BufferaMCPServer` использует строгую конфигурацию SDK и объявляет только `search_history`, `read_clip`, `get_neighbors`, все с read-only annotations. Схемы инструментов и фактическая валидация отклоняют неизвестные параметры, неверные типы и выход за границы. ID передаются строками, даты — ISO 8601 с часовым поясом. Успешный результат есть и в `structuredContent`, и как JSON в текстовом `content`; поля используют snake_case. Содержимое записей отмечено как недоверенные данные, а не инструкции. Контракт инструментов и ограничения изложены в [mcp.md](mcp.md).

`SerializedTransport` оборачивает `StdioTransport` SDK и последовательно отправляет целые сообщения. Это защищает фреймы от перемешивания, когда underlying actor приостанавливает запись большого ответа и принимает следующую отправку. Очередь завершается при ошибке записи, чтобы после возможного частичного JSON не дописать новый ответ; отключение отменяет ожидающие отправки. EOF завершает сервер и транспорт, SIGPIPE игнорируется для корректной обработки исчезнувшего клиента. В stdout идут только сообщения JSON-RPC, диагностические сообщения запуска — в stderr. Содержимое истории не журналируется.

`LiteralJSONTransport` устраняет ещё одну особенность SDK 0.12.1: его универсальный `Value` декодирует строки `data:` как бинарные данные и меняет их при повторном кодировании. На внутренней границе аргументы `tools/call` передаются как JSON-строка до собственного обработчика; наружу остаётся обычный MCP. В успешном ответе `structuredContent` восстанавливается из точного JSON в текстовом `content` уже после кодирования SDK. Поэтому запросы, фрагменты и полный текст сохраняются дословно. Инициализация, диспетчеризация, отмена и ошибки протокола остаются в SDK.

`MCPAccess` хранит явное разрешение в `Application Support/Buffera/mcp-access.json`, отдельно от UserDefaults и базы. Отсутствующий, повреждённый файл или неизвестная версия означают запрет. Изменение записывается во временный файл режима 0600 и публикуется атомарным rename. Новый каталог создаётся с режимом 0700. Настройки ничего не включают автоматически: вкладка «Агенты» читает актуальное состояние при показе, сохраняет checkbox и показывает ошибки рядом. Копирование конфигурации доступно и при выключенном разрешении; путь берётся из текущего bundle, JSON экранирует его. Callback в `AppDelegate` использует `ClipboardService.restore`, поэтому собственная конфигурация не попадает в историю. Настройки внешних агентов не изменяются.

Команды подключения Claude Code и Codex формирует `MCPAccess.addCommand`: выбор клиента типизирован, префиксы CLI фиксированы, путь к executable всегда заключён в POSIX-кавычки с экранированием апострофов. Все три кнопки используют один callback копирования; Buffera не запускает shell или CLI. Для Claude Code явно задан `--scope user`, поскольку история относится ко всему пользователю, а не к отдельному проекту.

`HistoryReader` — actor, который последовательно обслуживает чтение. Каждый вызов заново читает разрешение, открывает `HistoryStore(mode: .readOnly)` и проверяет разрешение ещё раз перед возвратом результата, в том числе при ошибке. Этот режим использует `SQLITE_OPEN_READONLY`: не создаёт каталог или базу, не включает WAL и не запускает миграции; принимает только текущую схему версии 10. Недоступная или несовместимая история даёт ошибку с предложением запустить актуальную Buffera. Для read-only соединения доступны те же операции хранения и нормализация поиска, что для UI, без дублирования SQL в MCP.

Поиск и соседи включают скрытые записи; `concealed_only` позволяет выбрать только их. Общий поисковый индекс скрытой записи содержит безопасное название и источник, без секрета или OCR. `search`/`count` и выбор опоры с соседями выполняются в согласованном read snapshot. `HistoryItem` маскирует скрытую карточку на границе MCP: принудительно задаёт заголовок «Скрытая запись», исключает `snippet`, `snippet_truncated`, `byte_count` и передаёт `is_concealed`. Дата, источник, тип, избранное и удалённое происхождение сохраняются. Эти карточки входят в `total` и лимиты страниц и соседей.

`HistoryReader.read` использует только `HistoryStore.visibleContent(id:)`, который допускает чтение нескрытых источников. До загрузки payload скрытая запись сразу даёт `content_kind: masked`, пустой текст, `offset: 0`, `is_complete: false` и сообщение о недоступности содержимого через MCP, без длины и продолжения. После декодирования состояние проверяется заново, чтобы скрытие во время операции не позволило выдать текст. Ошибки декодирования и проверки смещения также заменяются маской, если запись успела стать скрытой.

В MCP нет метода раскрытия или параметра обхода маскировки. Прямой вызов удалённого `reveal_clip` отклоняется диспетчером как неизвестный инструмент. Ни `markUsed`, ни изменения истории, ни доступ к NSPasteboard из helper не вызываются. Текущая история требует схемы 9; подключённые клиенты должны перезапустить старый helper после обновления.

`ClipboardText.decode` — общий декодер UTF-8/RTF для приложения и MCP. `read_clip` использует общий путь декодирования и пагинации: требует читаемый текст каждого элемента payload, чтобы не выдавать частичную запись за полную. Ответы делятся по Swift Character (графемным кластерам) с дополнительным лимитом UTF-8; продолжение задаётся `next_offset`. Картинки отдают только сохранённый OCR: helper не запускает распознавание и не читает бинарное изображение. Достижение OCR лимита 200 000 символов отмечается как возможная неполнота. Файлы возвращают пути из `public.file-url` без обращения к оригиналам; остальные форматы — только метаданные. Поиск и список соседей возвращают ограниченные заголовки и фрагменты, а не полный payload.

## Проверенные внешние контракты

| Граница | Источник | Защита |
| --- | --- | --- |
| Элементы буфера становятся недействительными после смены владельца | [NSPasteboardItem](https://developer.apple.com/documentation/appkit/nspasteboarditem) | Копирование Data, проверка changeCount |
| Нельзя повторно записывать объект, уже привязанный к буферу | Там же | Новые объекты при restore |
| Чтение может вернуть nil | [pasteboardItems](https://developer.apple.com/documentation/appkit/nspasteboard/pasteboarditems), data(forType:) | Пустой буфер пропускается; недоступный формат сообщает ошибку |
| Регистрация сочетания может конфликтовать | CarbonEvents.h из установленного SDK, RegisterEventHotKey | Проверка OSStatus, меню остаётся доступным |
| SQLite-операции могут завершиться ошибкой | sqlite3.h из установленного SDK | Проверка кодов, rollback, ошибка в меню |

## Отказы и восстановление

- Смена буфера во время чтения → снимок пропускается, следующее изменение читается новым циклом.
- Слишком большой элемент или недоступное представление → история не получает частичный элемент, ошибка доступна в меню, основной буфер не меняется.
- Ошибка записи/декодирования базы → сообщение, без сброса или пересоздания пользовательской истории.
- Ошибка миграции или ручного скрытия → rollback и сообщение, без частично изменённой записи; отсутствующий id при скрытии возвращает `HistoryError.missing`.
- Ошибка изменения избранного → сообщение и снятие блокировки действия; карточка меняется только после успешной записи. Отсутствующий id возвращает `HistoryError.missing`, история не пересоздаётся.
- Ошибка чтения или декодирования просмотра → сообщение внутри поповера; исходный payload и системный буфер не меняются. Поздний результат для другого выбора отбрасывается.
- Ошибка записи в системный буфер → окно остаётся открытым, сообщение. macOS не предоставляет транзакцию для clearContents/writeObjects; при отказе writeObjects прежнее содержимое может быть уже очищено.
- Ошибка экспорта → запись истории остаётся, сообщение; файл пишется атомарно.
- Ошибка очистки временного кеша → сообщение в меню; новый экспорт, если его подготовка/очистка не удалась, не открывается в Finder. Постоянные сохранения не зависят от этого кеша.
- Конфликт сочетания → сообщение с рекомендацией закрыть Pasta; история доступна через меню.
- MCP выключен или разрешение отозвано во время чтения → ошибка инструмента без содержимого истории; `initialize` и список инструментов остаются доступны.
- История для MCP отсутствует, недоступна или имеет другую версию схемы → ошибка без создания, миграции или пересоздания базы; обновление выполняет основное приложение.
- Клиент MCP закрыл stdin или оборвал соединение → сервер завершает транспорт; ошибка записи отменяет ожидающие ответы.
- Ошибка embedding-модели → индексация приостанавливается с возможностью повтора, поиск возвращается к словам; обычная история продолжает работать.
- Выключение модели во время индексации или поиска → worker завершается, незавершённые задания сохраняются; поздний ответ не применяется.
- Смена модели или правил подготовки текста → готовые векторы другой версии не смешиваются с новыми, производный индекс перестраивается.

## Следующие независимые расширения

OCR через Apple Vision (`VNRecognizeTextRequest`) уже формирует отдельный поисковый текст, не изменяя исходное содержимое. MCP уже предоставляет внешний доступ к поиску и чтению. Эмбеддинги остаются производным индексом, локальная LLM — необязательным потребителем общего поиска. Запись истории и обычный поиск не должны зависеть от их доступности. Согласованные этапы и отложенные идеи перечислены в [ideas.md](ideas.md).


## Полное переименование

Swift-пакет и executable — `Buffera`, основной модуль — `BufferaCore`, проверки — `BufferaChecks`; системный идентификатор — `local.buffera.app`. Перед созданием меню и открытием базы `AppDelegate` проверяет отсутствие предыдущей версии, затем вызывает `LegacyMigration`. Целиком перемещается прежняя папка истории в `Application Support/Buffera`: SQLite, WAL/SHM, резервные копии и постоянные экспорты. Два существующих каталога, файлы и символьные ссылки вызывают ошибку запуска; данные не объединяются и не перезаписываются.

Настройки переносятся в новый UserDefaults domain только по известным ключам. Имена рамок окон и положения значка преобразуются, существующие новые значения имеют приоритет. Старый домен остаётся для восстановления; маркер завершения записывается вместе со значениями. Новые временные экспорты используют новое имя; прежний кеш продолжает участвовать в очистке с общим лимитом 256 МиБ. Старые идентификаторы остаются только в совместимости и исторических протоколах проверки.
