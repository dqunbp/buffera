# Руководство Buffera

[← О проекте](../README.ru.md) · [Установка](#скачать) · [Управление](#управление) · [Поиск и ответы](#поиск-и-ответы) · [MCP](#подключение-агента-через-mcp) · [Хранение данных](#данные-и-ограничения) · [Сборка](#сборка-и-запуск)

Название отсылает к английскому `buffer` и русскому «буфера». Фирменный знак — пара округлых контуров: монохромный в строке меню, сиреневый на иконке приложения и в настройках. Пакет, исполняемый файл и модули называются Buffera, системный идентификатор — `local.buffera.app`.

Локальный менеджер истории буфера для macOS 14+. Swift + AppKit, системная SQLite и локальное распознавание текста через Apple Vision. Для подключения внешних агентов есть MCP через stdio на официальном Swift SDK. На Apple Silicon доступны поиск по смыслу через EmbeddingGemma 2 и встроенный чат по истории через Gemma 4.

Интерфейс доступен на русском и английском. В настройках на вкладке «Вид» можно выбрать системный язык (по умолчанию), русский или английский. Выбор сохраняется сразу и применяется после перезапуска Buffera. Системный режим выбирает первый поддерживаемый язык из предпочтений macOS; если подходящего нет, используется английский. Язык интерфейса не меняет содержимое истории, языки OCR или язык ответов помощника. Устройство ресурсов и правила добавления строк описаны в [docs/localization.md](localization.md).

## Скачать

[Скачать Buffera для Apple Silicon](https://github.com/dqunbp/buffera/releases/latest/download/Buffera-macOS-arm64.dmg) · [Все выпуски](https://github.com/dqunbp/buffera/releases) · [Сайт](https://buffera-soft-touch.dqunbp.chatgpt.site)

Поддержать разработку можно через кнопку внизу настроек. Она открывает [страницу Tribute](https://web.tribute.tg/d/SHI) в браузере. Донат добровольный и не открывает дополнительные функции.

Готовая сборка требует Mac с Apple Silicon и macOS 14 или новее. Открой DMG и перетащи Buffera в Программы. Модели для умных функций скачиваются отдельно в настройках приложения.

Текущие сборки подписаны ad-hoc, без Developer ID и нотарификации Apple. Если macOS блокирует запуск, после первой попытки открой «Системные настройки → Конфиденциальность и безопасность» и разреши запуск Buffera. [Инструкция Apple](https://support.apple.com/ru-ru/102445), [подробности установки на русском и английском](INSTALL.txt).

В «Настройки → Вид» можно выбрать системную, светлую или тёмную тему. Она применяется сразу ко всем окнам Buffera и сохраняется после перезапуска. Системный режим следует оформлению macOS.

В «Настройки → Клавиши» можно выбрать общую базу (`⌘⌥`, `⌃⌥`, `⌃⇧`, `⌘⇧` или `⌃⌘⌥`) и две разные буквы A–Z: открыть / следующая запись и предыдущая запись. «Применить» сохраняет пару без перезапуска; «По умолчанию» возвращает `⌘⌥V` / `⌘⌥C`. Буквы обозначают физические клавиши латинской раскладки и работают при переключении языка ввода. При конфликте с командами Buffera или ошибке регистрации прежняя пара сохраняется. Обратное сочетание перехватывается только при открытой истории. Ниже указаны сочетания по умолчанию.

## Обновления

Buffera проверяет последний стабильный выпуск GitHub Releases при запуске, затем раз в час проверяет, прошли ли сутки с последней попытки; та же проверка выполняется после пробуждения Mac. Фоновые запросы выполняются не чаще раза в сутки. При наличии новой версии с готовым DMG для Apple Silicon на значке Buffera в строке меню появляется небольшая точка. Панель истории не содержит уведомлений об обновлениях; фоновые проверки не открывают окна.

Откройте «Настройки → Обновления»: здесь указаны установленная и доступная версии. «Открыть релиз» ведёт на страницу GitHub с изменениями и скачиванием; «Пропустить эту версию» убирает точку до следующего выпуска, но сохраняет доступ к найденному релизу в настройках. Здесь же доступны «Проверить обновления…» и переключатель «Проверять обновления автоматически» для отключения фоновых запросов.

Проверка читает публичные сведения о релизе без GitHub-аккаунта; история буфера и содержимое записей не передаются. Найденная версия, пропуск и время последней попытки сохраняются локально. Ошибка сети не убирает уже найденное обновление; результат проверки отображается внутри настроек. Ограничение частоты запросов со стороны GitHub действует и при ручной проверке.

Установка выполняется вручную: скачайте DMG, завершите Buffera и замените приложение в папке установки. После обновления перезапустите подключённый MCP-процесс. Это проверка наличия релиза, а не автоматическая загрузка или установка. В версии 0.2.0 этой возможности нет; для перехода на 0.3.1 или новее скачайте выпуск с GitHub вручную.

## Сборка и запуск

Нужны Command Line Tools со Swift 6.4 или новее: эта версия требуется текущим зафиксированным транзитивным зависимостям MCP SDK. Минимальная система готового приложения остаётся macOS 14. Полный Xcode не обязателен. Прямая зависимость SwiftPM — `modelcontextprotocol/swift-sdk` версии `0.12.1`; разрешённые версии зависимостей сохранены в `Package.resolved`.

```sh
zsh scripts/build-app.sh
open dist/Buffera.app
# Упаковка готовой arm64-сборки в DMG:
zsh scripts/package-release.sh
```

Версия приложения, номер сборки и версия MCP задаются в `Sources/BufferaCore/AppVersion.swift`. Тег релиза имеет вид `vX.Y.Z`. Команда `zsh scripts/create-release.sh` собирает код из тега и создаёт черновик GitHub Release с DMG и SHA-256. Подготовка тега, публикация и восстановление после ошибок описаны в [docs/releases.md](releases.md).

В среде, где запрещён вложенный `sandbox-exec`, передайте `--disable-sandbox` скрипту сборки. Это отключает только песочницу манифеста SwiftPM, а не защиту macOS приложения.

Получается локально подписанный ad-hoc пакет `dist/Buffera.app` с основным приложением и отдельным исполняемым файлом `Contents/MacOS/BufferaMCP`. На Apple Silicon сборка также скачивает закреплённый выпуск llama.cpp, проверяет SHA-256 и включает движок с `BufferaModelProbe` для проверки моделей, `BufferaEmbeddingWorker` для поиска и `BufferaChatWorker` для чата. sqlite-vec 0.1.9 собирается статически из закреплённого исходника. Веса в пакет не входят. Для распространения без предупреждения о неизвестном разработчике нужны Developer ID и notarization. Можно скопировать пакет в Applications. Для автозапуска добавьте его в «Системные настройки → Основные → Объекты входа».

Если Documents обслуживается файловым провайдером, тот может повторно добавить FinderInfo к собранному `.app`, нарушив строгую проверку подписи. Запускайте рабочую копию вне синхронизируемой папки, например из `~/Applications/Buffera.app`. Копирование без служебных атрибутов: `ditto --norsrc --noextattr dist/Buffera.app ~/Applications/Buffera.app`, затем `codesign --force --sign - ~/Applications/Buffera.app`.

Перед запуском закройте Pasta, если она занимает `⌘⌥V`. Buffera не вставляет автоматически и не запрашивает Accessibility для синтетического нажатия клавиш. macOS может отдельно запросить доступ к буферу обмена: для фоновой истории его нужно разрешить.

## Поиск и ответы

В «Настройки → Поиск и ответы» независимо включаются «Поиск по смыслу» и «Спросить Buffera». В каждой карточке сразу видны назначение, название и размер модели: EmbeddingGemma 2 — около 310 МБ для поиска, Gemma 4 E2B — 2,84 ГБ для помощника. Первый запуск выполняется явной кнопкой «Скачать модель и включить». После скачивания и проверки функция включается автоматически; готовую модель можно использовать повторно обычным переключателем. Загрузку можно поставить на паузу и продолжить, в том числе после перезапуска. Выключение сохраняет модель; «Удалить модель» освобождает место. Лицензия и проверка на встроенных примерах находятся в «Подробнее».

Включение поиска по смыслу запускает постепенную подготовку текста и OCR истории. В карточке функции видны прогресс, частично обработанные длинные записи и возможность повторить обработку после ошибки. Выключение останавливает обработку и освобождает память; файлы и индекс сохраняются для продолжения.

В окне истории флажок «Искать также по смыслу» дополняет точные совпадения результатами по смыслу, сохраняя все фильтры. Точные совпадения идут первыми; смысловых дополнений — до 200. Если снять флажок, поиск использует только совпадения текста. Пустой запрос, выключенная или недоступная модель оставляют обычный поиск. Скрытые записи не индексируются по содержимому; файлы на диске не открываются.

Смысловой индекс готовится для видимого текста, ссылок, путей файлов и OCR картинок. Для длинной записи обрабатывается до 128 КиБ текста и 32 фрагментов по 512 токенов, с перекрытием 64 токена; неполнота отмечается в прогрессе. Исходное содержимое сохраняется. Подробности хранения, версий и движка описаны в [models.md](models.md).

На аккумуляторе фоновая подготовка поиска по смыслу по умолчанию приостанавливается. В карточке видны причина, прогресс и кнопка «Продолжить сейчас»; при подключении питания очередь продолжается автоматически. Поиск по готовым записям и вопросы помощнику остаются доступны. Настройку «только при питании от сети» можно выключить; режим энергосбережения macOS и сильный нагрев также приостанавливают фоновые вычисления. Подробнее — [расход заряда и управление очередью](models.md#расход-заряда).

## Спросить Buffera

Кнопка «Спросить» рядом с флажком поиска по смыслу и пункт меню «Спросить Buffera…» открывают локальную языковую модель (LLM) с доступом к истории буфера обмена. В «Настройки → Поиск и ответы» нажмите «Скачать модель и включить», либо включите функцию, если модель уже скачана. Поиск по смыслу подключается независимо: без него помощник ищет по словам.

Можно спросить, например: «Какую ошибку подключения я копировал вчера?» или «Что было рядом с этой записью?». Помощник ищет, читает найденное и при необходимости получает соседние копирования. Ответ появляется постепенно. Под ним находятся кнопки источников с приложением и временем копирования; нажатие открывает запись среди соседей, не меняя буфер.

Enter отправляет вопрос, Shift+Enter добавляет строку. «Остановить» или Escape во время ответа отменяет генерацию. Закрытие окна также останавливает ответ, сохраняя разговор до завершения Buffera; «Новый разговор» очищает его. Переписка не записывается на диск. Скрытые записи в чат не попадают; если источник скрыт или удалён, связанный разговор сбрасывается. Встроенному чату не требуется разрешение для внешних агентов MCP.

Ответ строится по ограниченному набору найденных записей: это не полный анализ всей истории. Длинные документы и ответы могут быть сокращены; интерфейс сообщает об этом. Пути файлов читаются как текст, сами файлы не открываются.

## Управление

Миниатюры хранятся в `~/Library/Caches/Buffera/Thumbnails` (до 64 МБ и 512 файлов). При запуске и открытии истории Buffera использует этот кэш или байты изображения, сохранённые в истории, не обращаясь к исходным файлам. Если запись содержит только путь и миниатюры нет, показывается значок файла. Явный просмотр через Пробел или `⌘Y` может открыть оригинал и запросить доступ к его папке; полученная миниатюра сохраняется для следующих запусков. Скрытые записи не кэшируются; скрытие и удаление очищают их миниатюры. Кэш можно удалить: картинки из сохранённых байтов восстановятся автоматически, для записей только с путём потребуется снова открыть просмотр.

Карточки можно перетаскивать в другие приложения: текст и ссылки — в редакторы и поля ввода, изображения и файлы — в области загрузки, чаты и Finder. Передаётся полное содержимое со всеми сохранёнными форматами, включая RTF/HTML и специальные данные приложений; несколько объектов в записи остаются отдельными объектами. Для изображений дополнительно создаются временные файлы, доступные принимающему приложению после завершения drop. Поддержка конкретных форматов зависит от получателя; приём через `⌘V` не гарантирует поддержку перетаскивания.

Перетаскивание выполняет только копирование: исходные файлы и запись остаются на месте, общий буфер не меняется. Исходные файлы и папки должны быть доступны по сохранённым путям; если хотя бы один недоступен, вся операция отменяется с сообщением. Скрытые записи имеют нейтральный предпросмотр без содержимого. Escape, отпускание мыши до завершения подготовки и отклонённый drop не меняют порядок истории; принятый drop учитывается как использование, сохраняя исходную дату копирования.

Якорь внизу истории закрепляет окно: оно остаётся поверх других приложений при переключении между ними. Повторное нажатие возвращает обычное автозакрытие. `⌘⌥V` сначала возвращает фокус в закреплённую историю, сохраняя запрос, выбор и положение списка. Escape и подтверждённое копирование закрывают окно; само закрепление сохраняется до выхода из Buffera. Скрытый текст снова маскируется при переходе в другое приложение.

| Действие | Клавиши |
| --- | --- |
| Открыть историю / следующий элемент | `⌘⌥V` |
| Предыдущий элемент, пока окно открыто | `⌘⌥C` |
| Перемещаться между строками списка или сетки | `↑` / `↓` |
| Перемещаться между соседними карточками вне поля поиска | `←` / `→` |
| Поместить выбранное в буфер и закрыть окно | `Enter` или двойной щелчок |
| Сразу выбрать одну из первых девяти записей текущего списка | `⌘1`–`⌘9` |
| Открыть просмотр выбранной записи | `Пробел` при фокусе в списке; `⌘Y` также из поиска |
| Добавить в избранное / убрать из него | `⌘D` |
| Показать записи рядом по времени копирования | `⇧⌘N` |
| Скрыть содержимое / временно показать скрытое | `⇧⌘H` |
| Показать картинку в Finder | `⇧⌘R` |
| Сохранить картинку в выбранную папку | `⇧⌘S` |
| Перейти к поиску | `⌘F` |
| Переключить фокус между поиском и карточками | `Tab` |
| Показать / скрыть боковое меню фильтров | `⌘⌥S` |
| Открыть настройки внешнего вида | `⌘,` |
| Очистить запрос и фильтры, вернуться ко всей истории | `⌘0` |
| Отменить без изменения буфера | `Esc` |
| Удалить выбранную запись | `⌘⌫` |

Одиночное нажатие `⌘⌥V` активирует Buffera и открывает окно с фокусом в карточках. Если сразу отпустить клавиши, окно остаётся в обычном режиме: дальнейшие `⌘⌥V/C` только двигают выбор и больше не включают автозакрытие до следующего открытия. Для быстрого выбора нужно непрерывно удерживать `⌘⌥` с самого открытия и ещё раз нажать V или C: V выбирает следующую запись, C — предыдущую. Отпускание `⌘` или `⌥` после такого перебора помещает выбранную запись в буфер и закрывает окно. Открытие через меню или значок приложения также оставляет окно в обычном режиме; автоматический повтор от удержания самой V не включает перебор. В сетке `↑/↓` переходят на строку вверх или вниз, `←/→` — к соседней карточке. Enter, кнопка «В буфер» в карточке или двойной щелчок фиксируют запись, помещают её содержимое в системный буфер и закрывают окно, возвращая фокус предыдущему приложению. Вставка выполняется пользователем в целевом приложении (обычно `⌘V`; Buffera не меняет пользовательские переназначения). В обычном списке Escape или переход в другое приложение закрывают окно без подтверждения; Escape также отменяет ещё не завершённое подтверждение. В просмотре и режиме соседей Escape сначала возвращает на предыдущий уровень.

После успешного выбора запись поднимается наверх без дубликата; дата копирования, приложение, избранное и маска сохраняются. В обычной истории при следующем открытии выбрана эта запись. Esc и переход в другое приложение сохраняют выделение без копирования и перестановки. Новое внешнее копирование (в том числе повторное) становится первым и выделенным, если подходит под текущие фильтры; иначе выделение в отфильтрованном списке сохраняется.

Начните печатать при фокусе в списке, чтобы начать новый поиск. `⌘F` переводит фокус в существующий запрос для редактирования; пробелы в поле поиска остаются обычными пробелами. При быстром повторном открытии сохраняются запрос, фильтры, раздел «История»/«Избранное» и выбранная запись. По умолчанию после минуты с закрытым окном следующий вызов показывает пустой поиск, всю историю без фильтров и первую запись. Открытое окно не сбрасывается. В «Настройки → История» можно выключить этот сброс или задать время от 1 до 1440 минут; настройки действуют сразу. После перезапуска приложения состояние окна также сбрасывается. Вернуться ко всей истории можно кнопкой сброса рядом с поиском или `⌘0`.

Через маленький значок планшета с зажимом справа в верхней системной строке меню тоже можно открыть историю. В его меню виден статус `⌘⌥V`; при конфликте доступно повторное подключение сочетания. Обычное копирование `⌘C` остаётся доступно в поле поиска.

Карточки расположены списком или сеткой; боковое меню с типами, периодом и приложениями можно скрыть кнопкой слева от поиска или `⌘⌥S`. Активные фильтры при этом сохраняются, а тип, дата и приложение доступны через значок фильтров рядом с поиском. В каждой карточке находятся содержимое, приложение, дата и действия: избранное, просмотр, копирование и доступные для её типа скрытие или экспорт. Кнопки видны постоянно, без наведения. Названия действий и сочетания клавиш видны в подсказках; контекстное меню содержит те же действия и удаление. Удержание `⌘` показывает номера первых девяти записей для быстрого выбора. Выбранная карточка выделена обводкой. Звезда обновляет карточку на месте; снятие звезды в избранном убирает только эту запись.

Тип «С устройств» показывает новые записи с маркером Universal Clipboard; в карточках они подписаны «С другого устройства». Имя устройства и приложение на нём неизвестны, приложение Mac им не присваивается. «Скрытые» показывает автоматически помеченные и вручную скрытые записи. «С устройств» и «Скрытые» находятся в общем выборе типа вместе с текстом, ссылками, картинками, файлами и данными. Одновременно выбран один тип; он сочетается с поиском, датой, приложением и избранным. Старые записи не помечаются как удалённые задним числом: раньше этот признак не сохранялся.

Просмотр по пробелу или кнопке в карточке открывается временно рядом со списком. В нём можно прочитать длинный текст, рассмотреть картинку, увидеть пути файлов или перечень других форматов. Пробел и Escape закрывают просмотр, Enter выбирает запись, стрелки возвращают к списку и меняют выбор. Полный текст не показывается при случайном наведении. Скрытую запись сначала нужно явно раскрыть кнопкой «Показать содержимое».

«Скопировать иначе» — подменю по правому клику на карточке. Кнопка в карточке и `⇧⌘C` открывают тот же список. Выбор действия сразу копирует результат и закрывает историю. Дополнительного окна и подтверждения нет; `Esc` закрывает меню без копирования.

Показываются только подходящие варианты: «Без форматирования» для читаемого текста, «Форматировать JSON» для корректного JSON, который требует форматирования, «Убрать переносы строк» для соседних непустых строк, «Убрать повторяющиеся строки» при наличии повторов и «Убрать метки из ссылки» для ссылки с удаляемыми метками. Для картинки доступен «Текст с картинки» через существующий OCR; если готовое распознавание уже показало отсутствие текста, пункт скрыт. Открытие меню само не запускает распознавание. Действия недоступны для скрытых записей.

Список проверяется по полному содержимому в фоне; при первом открытии может кратко появиться «Проверяем варианты…». Каждый вариант применяется к исходному содержимому. Для текста и ссылок доступны также «Как файл .txt» и «Как файл .md»: полный текст сохраняется в UTF-8 без изменения содержимого, а в буфер помещается файл для вставки в Finder или приложения, принимающие вложения. Имя выбирается в «Настройки → История → Имя текстового файла»: первая непустая строка (по умолчанию) или дата и время копирования. Начальные маркеры Markdown-заголовка и недопустимые символы удаляются, длинное имя сокращается; если подходящего имени нет, используется дата. Файлы разных записей с одинаковыми именами не перезаписывают друг друга. Файлы используют временный кеш экспорта с очисткой по возрасту и размеру. Остальные варианты копируют результат как обычный текст; исходные форматы, дата копирования, источник, избранное и маска записи сохраняются. Как при обычном копировании, запись поднимается наверх, без создания дубликата.

Форматирование JSON меняет только пробелы и отступы: большие числа, повторяющиеся ключи и экранирование сохраняются. Очистка переносов оставляет абзацы, удаление повторов сохраняет порядок первых строк и пустые строки. Очистка одной HTTP(S)-ссылки удаляет `utm_*`, `fbclid`, `gclid`, `dclid`, `msclkid`, `yclid`, `mc_cid`, `mc_eid`, `gbraid`, `wbraid`; остальные параметры и фрагмент остаются прежними. Ссылка с распознанной подписью не изменяется, если удаление меток может её нарушить.

При ошибке история остаётся открытой, а буфер не меняется. Пока идёт обработка, `Esc` отменяет ожидающее копирование. Для обработки текста действует предел 2 МиБ на вход и результат и 128 уровней JSON; «Без форматирования» читает полный текст без этого ограничения. OCR с достигнутым пределом 200 000 символов не выдаётся за полный результат. Модели и сеть для этих действий не нужны.

«Что копировал до и после» открывается кнопкой часов в карточке, через её контекстное меню или `⇧⌘N`. Видны опорная запись и до 10 ближайших копирований до и после неё, от новых к старым. Соседи берутся из всей истории: запрос, тип, период, приложение и раздел избранного временно не ограничивают список. Скрытые записи остаются под маской. При открытии опора располагается по центру видимой области, насколько позволяют границы списка. Она отмечена цветной точкой и обводкой даже после перехода на соседнюю карточку; повторите действие у другой записи, чтобы пройти дальше по истории.

«Назад в историю» или `Esc` возвращает исходные запрос, фильтры, выделение и прокрутку. Если открыт просмотр, первый `Esc` закрывает его, следующий возвращает результаты. Новые копирования не переставляют соседей во время просмотра; при возвращении результаты обновляются при необходимости. Закрытие окна завершает временный режим, а при следующем открытии восстанавливается исходный поиск. Порядок соседей определяется последним внешним копированием, а не выбором записи в Buffera. Повторное копирование одинакового содержимого заменяет прежнюю дату и источник: полного журнала повторов пока нет. Функция работает и на старой истории, без моделей и миграции базы.

Шестерёнка справа от поиска, `⌘,` и пункт «Настройки…» в системном меню открывают отдельное окно настроек. Вкладки «Вид», «История», «Клавиши» и «MCP» объединяют компоновку, лимиты хранения, подсказки сочетаний и доступ через MCP. Повторное открытие поднимает то же окно; его закрытие не завершает приложение. Настройки вида и лимитов применяются сразу; смена языка — после перезапуска. Сочетания сохраняются кнопкой «Применить», остальные настройки — сразу. Доступны обычное окно и панели у левого или правого края экрана. Обычное окно можно перемещать за свободную область и растягивать за края; его положение и размер сохраняются отдельно от ширины боковой панели. Панель занимает доступную высоту экрана, допускает изменение ширины и появляется сразу у выбранного края без анимации открытия. При закрытии панель сдвигается за край; системное «Уменьшить движение» отключает эту анимацию. Стандартные кнопки закрытия, сворачивания и разворачивания скрыты; окно закрывается через Escape или выбор записи.

Можно выбрать 1–4 колонки и плотность в 3–12 видимых строк. Одна колонка даёт список, несколько — сетку. В обычном окне карточки имеют одинаковую высоту, минимум 96 точек. В боковых панелях высота зависит от содержимого: короткий текст занимает от 74 точек, длинный растёт до высоты, заданной плотностью. У картинок остаётся место под миниатюру и действия, а карточки одной строки сетки выравниваются по самой высокой. Минимальная ширина карточки — 230 точек, поэтому в узком окне колонок может быть меньше. Размер окна ограничивается видимой областью экрана; при отключении монитора обычное окно возвращается на доступный экран. Фон использует системную полупрозрачность с размытием, а текст остаётся непрозрачным. Вид эффекта зависит от темы и системной настройки «Уменьшить прозрачность».

## Что входит

- Захват новых копирований каждые 400 мс, пока приложение запущено и сеанс Mac доступен. При блокировке, смене пользователя или сне захват приостанавливается; накопленное за это время пропускается при возвращении, ручная пауза остаётся в силе.
- Сохранение доступных бинарных представлений каждого элемента, включая текст, RTF, PNG/TIFF, ссылки, группы файлов и пользовательские форматы.
- Повторное копирование одинакового содержимого поднимает существующую запись наверх; дата и приложение заменяются данными последнего копирования. Маска и отметка избранного сохраняются.
- Поиск по всем словам запроса без учёта регистра, по фрагментам текста, распознанному тексту картинок, имени файла и названию приложения. Символы `%` и `_` ищутся буквально. Поиск по смыслу подключается отдельно; его настройка описана выше.
- Боковое меню с типами, периодом и приложениями. Компактное меню фильтров рядом с поиском доступно и при скрытом сайдбаре; «Сбросить фильтры» очищает их вместе, сохраняя поисковый запрос.
- В календарном поповере доступны «Всё время», «Сегодня», «Вчера», «7 дней», «30 дней» и два календаря для границ периода. Последний выбранный день включается целиком; обратный порядок дат исправляется автоматически. Периоды в 7 и 30 дней включают сегодня, даты используют локальный часовой пояс macOS.
- Фильтр приложения выбирает точное имя источника последнего копирования из имеющейся истории и сочетается с текстом, типом и датой. Имена отсортированы без учёта регистра; сама Buffera не предлагается в списке источников, но её записи остаются в общей истории. Источник определяется по метаданным буфера, когда они доступны; иначе используется активное приложение.
- Звезда в карточке добавляет запись в избранное. Раздел «Избранное» сочетается с поиском и всеми фильтрами; записи сохраняются после перезапуска и защищены от автоматической очистки истории.
- Страницы по 150 записей, подгружаемые при прокрутке. Полные двоичные данные читаются отдельно от списка.
- PNG/TIFF можно экспортировать в PNG: «Сохранить как…» создаёт постоянный файл в выбранном месте, «Показать в Finder» — временный файл с автоматической очисткой.
- Помеченные конфиденциальные записи по умолчанию пропускаются; при включённом зашифрованном хранении показываются под точками. Обычный текст или ссылку можно скрыть вручную. «Показать» временно раскрывает содержимое выбранной скрытой записи.
- Пауза записи, удаление отдельных записей, лимиты количества и объёма в меню.

## Первоначальная настройка

При первом запуске открывается отдельное окно настройки: язык и тема, окно истории, основные клавиши, хранение, MCP, поиск и ответы. Любой шаг можно пропустить. «Настроить позже» и закрытие окна отменяют весь черновик; повторно открыть визард можно через «Настроить Buffera…» в меню или «Пройти настройку заново…» в настройках.

До «Применить и начать» разрешение MCP и параметры моделей не меняются, загрузки не начинаются. Пропуск шага при повторной настройке сохраняет прежние значения. Новый язык применяется после перезапуска; тема — при завершении настройки, с предварительным просмотром в окне визарда.

Под поисковой строкой доступна настройка поиска по смыслу, даже когда модель ещё выключена. Во время загрузки и подготовки виден её статус; обычный поиск продолжает работать. Первый вызов «Что копировал до и после» открывает объяснение в отдельном окне. После подтверждения появляется выделенный заголовок режима, отметка исходной записи и кнопка возврата к прежнему списку. Объяснение можно открыть повторно кнопкой «?».

## Подключение агента через MCP

1. Откройте «Настройки → MCP» и включите «Разрешить агентам читать историю». По умолчанию доступ выключен.
2. Команды для Claude Code и Codex, а также JSON-конфигурация показаны полностью. Нажмите «Скопировать» у нужного блока; подтверждение рядом уточнит, что именно скопировано. Команду выполните в Терминале, JSON добавьте в настройки агента. Все варианты содержат абсолютный путь к `BufferaMCP` внутри запущенного пакета приложения; после перемещения пакета скопируйте его заново.
3. Переподключите MCP в агенте. Он сам запускает файл и общается с ним через stdin/stdout, без сетевого порта и отдельного постоянно работающего сервиса.

Агент получает три инструмента: `search_history` — общий поиск по словам и смыслу с фильтрами, `read_clip` — чтение записи, `get_neighbors` — соседние копирования. Поиск использует включённую embedding-модель и подготовленную часть индекса; без них работает по словам. Скрытые записи видны в поиске и соседях как «Скрытая запись», с датой, приложением и другими метаданными, но без фрагмента текста и размера. Их можно найти по метаданным, но не по словам из скрытого текста, OCR или смысловым векторам. `read_clip` также возвращает маску.

Содержимое скрытых записей недоступно через MCP, включая прямые вызовы инструментов. Раскрыть запись можно только в интерфейсе Buffera. После обновления приложения перезапустите подключённый MCP-процесс, чтобы он использовал новый набор инструментов.

Все инструменты только читают: MCP не меняет историю, порядок записей или системный буфер. Текст и ссылки читаются из полного сохранённого содержимого; для картинок доступен только уже готовый OCR, для файлов — только сохранённые пути без чтения файлов с диска.

Доступ можно выключить в той же вкладке: уже запущенные процессы проверяют разрешение при каждом обращении. Конфигурацию разрешено скопировать заранее при выключенном доступе; копирование само его не включает. Buffera не изменяет настройки внешних агентов. Содержимое разрешённых записей попадает в контекст выбранного агента, и дальнейшая обработка зависит от него.

После первоначального запуска Buffera и включения доступа MCP может читать сохранённую историю даже при закрытом приложении. Новые копирования и OCR пополняются, пока работает сама Buffera. Эмбеддинги и встроенная разговорная модель для подключения не нужны. Параметры инструментов, ограничения ответов и диагностика описаны в [docs/mcp.md](mcp.md).

## Поиск по тексту на картинках

Новые и уже сохранённые записи-картинки PNG/TIFF распознаются в фоне последовательно, по одной картинке за раз. [Apple Vision работает на устройстве](https://developer.apple.com/documentation/vision/recognizing-text-in-images), без отправки изображений в сеть. Используется точный режим с автоопределением языка; русский и английский выбираются из языков, доступных в установленной macOS. Их поддержка зависит от версии системы.

Распознанный текст дополняет обычный поиск и хранится отдельно, до 200 000 символов на запись. Исходная картинка и её форматы сохраняются: выбор найденной записи по-прежнему копирует картинку. Изображение уменьшается до 4096 пикселей по длинной стороне с учётом поворота. Обрабатывается первый кадр или страница каждого элемента буфера; PNG и TIFF одного элемента не дублируются. Ссылки на файлы не открываются, содержимое файлов на диске не распознаётся.

Картинка без текста считается обработанной. Ошибка не мешает остальной очереди: повторить неудачные попытки можно через «Повторить распознавание» в меню значка Buffera; они также повторяются при следующем запуске. Там же виден прогресс. Скрытые записи не распознаются и не участвуют в поиске по OCR; при скрытии уже обработанной записи её распознанный текст удаляется из индекса.

## Данные и ограничения

При первом запуске после переименования приложение переносит прежний каталог истории целиком, включая SQLite WAL, резервные копии и сохранённые экспорты, и копирует настройки в новый системный домен. Перенос выполняется только после закрытия предыдущей версии. Существующие новые настройки имеют приоритет; при конфликте двух каталогов приложение показывает ошибку, ничего не объединяя и не перезаписывая. Старые настройки остаются для восстановления.

История находится в `~/Library/Application Support/Buffera/`: `history.sqlite`, служебные файлы SQLite и отдельное разрешение `mcp-access.json`. Текущая версия схемы — 7. Базы версий 0–6 обновляются автоматически в одной транзакции: добавляются недостающие признаки скрытой записи, избранного, удалённого происхождения, отдельная таблица OCR, порядок последнего использования и таблицы смыслового индекса. Порядок первоначально совпадает с датой копирования, поэтому миграция не переставляет записи. Обычные картинки из старой истории ставятся в очередь распознавания; смысловой индекс начинает готовиться только после включения embedding-модели. Существующие идентификаторы, записи и исходное содержимое сохраняются. Неизвестная более новая версия не понижается.

Тип «Данные» объединяет форматы, для которых пока нет отдельного распознавания: внутренние объекты приложений, а также некоторые стандартные представления без поддерживаемого текстового или графического варианта. Исходные доступные форматы сохраняются для обратной вставки; пробел показывает их перечень.

«Показать в Finder» создаёт PNG в системной временной папке `$TMPDIR/local.buffera.app/ImageExports/`. Повторный показ той же картинки обновляет временный файл и срок хранения. Файлы старше 24 часов с последнего показа удаляются при запуске, раз в час, пока Buffera работает, и при новом экспорте. При превышении 256 МиБ удаляются самые старые файлы; текущий экспорт сохраняется. macOS также может очистить временную папку. Временные экспорты прежней установки продолжают очищаться по тем же правилам.

Для постоянного файла используйте «Сохранить как…» или скопируйте временную картинку в свою папку: независимую копию очистка Buffera не затронет. Исходная картинка остаётся в истории в пределах её лимитов. Папка `~/Library/Application Support/Buffera/Exports/`, созданная прежней версией и перенесённая вместе с историей, автоматически не очищается.

Лимиты меняются в «Настройки → История». По умолчанию сохраняется до 50 000 обычных записей и 5 ГБ их сериализованного содержимого. Оба ограничения применяются в транзакции после нового копирования; удаляются записи из конца обычной истории по времени последнего копирования или выбора. Избранные записи не расходуют эти лимиты и не удаляются автоматически, поэтому суммарный объём истории может превышать установленный лимит. Снятие звезды само по себе ничего не удаляет: запись снова участвует в очистке при следующем копировании. Явное удаление записи работает и для избранного. Лимит объёма считает исходное содержимое: OCR, смысловые векторы и скачанные модели занимают дополнительное место. Размер самого файла SQLite может оставаться больше после удаления записей: свободные страницы переиспользуются. Экспортированные картинки в лимит истории не входят: временные файлы имеют отдельные ограничения, постоянные сохраняются до удаления пользователем.

Одна запись ограничена 64 МБ исходных представлений, индексируемый текст — 200 000 символов. Содержимое при этом сохраняется полностью в пределах 64 МБ. О пропусках или ошибках можно узнать через «Последняя ошибка…» в меню. Буфер, существовавший до запуска, не импортируется автоматически.

В «Настройки → История → Секреты в истории» доступны два режима: «Не сохранять секреты» (по умолчанию) и «Сохранять секреты зашифрованными». Секреты распознаются по маркерам `org.nspasteboard.ConcealedType` и `com.agilebits.onepassword`. В первом режиме Buffera пропускает всю группу до чтения содержимого; во втором сохраняет все её представления зашифрованными. Обычные записи хранятся как раньше.

Список показывает точки и замок. Содержимое секрета не попадает в заголовок, поиск, OCR, смысловой индекс или MCP. Найти запись можно по безопасному названию, приложению и дате; эти метаданные остаются открытыми. «Показать» временно раскрывает текст в Buffera, копирование восстанавливает исходные форматы с маркером конфиденциальности.

Если приложение не пометило пароль, он сохраняется как обычный текст: автоматического определения паролей по содержимому нет. Команда «Скрыть» для сохранённого текста или ссылки шифрует payload и удаляет открытые текст и индексы независимо от режима захвата. При доступном ключе повторное копирование того же payload сохраняет секретность. При недоступном ключе новые записи без маркера обрабатываются как обычные; данные с маркером никогда не сохраняются открытыми.

Шифрование — AES-256-GCM с новым nonce при каждой записи. Случайный ключ хранится в Связке ключей macOS с доступом основного приложения; MCP не получает ключ. При отказе Keychain секрет пропускается с сообщением об ошибке, без отката к открытому хранению. macOS может запросить разрешение на доступ к ключу, особенно после обновления приложения с временной ad-hoc подписью. Потеря ключа делает сохранённые секреты невосстановимыми.

Переключение на «Не сохранять» влияет на новые копирования: существующие секреты остаются зашифрованными и доступны в Buffera. Старые скрытые записи автоматически шифруются при запуске; если доступ к ключу не удалось получить, они остаются недоступны для раскрытия до успешной повторной попытки. Её можно выполнить, выбрав зашифрованное хранение в настройках. При переводе открытой записи в секрет SQLite очищается от старых страниц и WAL; если другой процесс удерживает снимок базы, очистка откладывается до следующей попытки. Старые резервные копии и снимки диска это не изменяет.

Записи с `TransientType` или `AutoGeneratedType` пропускаются. При наличии конфиденциального маркера действует выбранный режим секретов.

Файлы сохраняются как ссылки на оригиналы, а не резервные копии. Удалённый или перемещённый оригинал не восстанавливается. Отложенные file promises и данные, которые приложение-источник не отдаёт, пока не материализуются в самостоятельные файлы. В этом случае запись может быть пропущена с сообщением. Не все специфические форматы приложений проверены.

## Проверка

```sh
CLANG_MODULE_CACHE_PATH="$PWD/.build/ModuleCache" \
SWIFTPM_MODULECACHE_OVERRIDE="$PWD/.build/ModuleCache" \
swift run --cache-path "$PWD/.build/cache" BufferaChecks
swift build --product BufferaMCP
swift run --cache-path "$PWD/.build/cache" BufferaMCPChecks
swift build --product Buffera
.build/debug/Buffera --smoke-test
.build/debug/Buffera --ocr-smoke-test
```

Smoke-проверка использует отдельный именованный системный буфер и не меняет основной буфер пользователя. `--ocr-smoke-test` проверяет настоящий Vision на искусственных изображениях, поиск в отдельной временной базе и фоновую очередь; пользовательская история и буфер не читаются. Ограниченная среда запуска может блокировать Vision: OCR-проверку нужно запускать в обычном пользовательском окружении. Проверки не требуют XCTest или полного Xcode.

`zsh scripts/check-copy-transform.sh` проверяет преобразования текста и копирование файлов `.txt`/`.md` через отдельный тестовый буфер.

`zsh scripts/check-history-panel.sh` проверяет панель в двух локалях, карточки и drag-and-drop. Для одного набора можно передать `ClipDragChecks`. После сборки `.build/localized-panel-checks/ClipDragChecks --interactive` открывает отдельный стенд с реальной панелью, тестовыми записями, нативным редактором и локальной веб-формой. Флажок `Delay preparation 2s` позволяет проверить отпускание мыши и Escape до готовности данных. Стенд не использует пользовательскую историю и не записывает общий буфер; результаты drop выводятся также в `/tmp/buffera-drag-ui.log`.

Ручная проверка: скопировать текст/картинку/несколько файлов, вызвать окно, отпустить клавиши (окно должно остаться), перебрать стрелками, нажать Enter (окно должно закрыться), затем вставить в исходное приложение. Повторно открыть через `⌘⌥V`, не отпуская `⌘⌥`, нажать V/C ещё раз и отпустить модификаторы: выбранная запись должна скопироваться, окно — закрыться. Отдельные одиночные нажатия с отпусканием каждый раз не должны закрывать окно. Прокрутить вниз, закрыть и снова открыть: видимые записи должны появиться сразу. Проверить действия карточки и их подсказки, `⌘1`–`⌘9`, просмотр по пробелу и `⌘Y`, избранное после повторного копирования и перезапуска, сохранение поиска между открытиями и явный сброс `⌘0`. Проверить Esc, фильтр приложения, календарь, временный экспорт, «Сохранить как…» и скрытие/временный показ на тестовом содержимом. Выполненные проверки и их ограничения перечислены в [docs/verification.md](verification.md).
