# Локальные модели

В «Настройки → Модели» можно подготовить две независимые модели. Поиск по смыслу и чат подключаются на следующих этапах; обычный поиск, OCR и MCP работают без скачивания моделей.

| Назначение | Модель и формат | Размер файла |
| --- | --- | --- |
| Поиск по смыслу | EmbeddingGemma 2, текстовая часть, GGUF Q8_0 | 309 855 456 байт |
| Локальный помощник | Gemma 4 E2B IT, GGUF Q4_0 | 2 841 481 184 байта |

Это размер загрузки, а не обещание расхода оперативной памяти. Обе модели распространяются по Apache 2.0. Каталог использует открытые репозитории [EmbeddingGemma 2](https://huggingface.co/ggml-org/embeddinggemma-2-GGUF) и [Gemma 4 E2B IT](https://huggingface.co/ggml-org/gemma-4-E2B-it-GGUF) организации ggml-org. Учётная запись и токен Hugging Face не нужны.

## Управление

- «Скачать» начинает загрузку выбранной модели. Размер виден заранее.
- «Пауза» сохраняет уже скачанную часть. «Продолжить» использует её и после перезапуска Buffera. При запуске приложения загрузки автоматически не возобновляются.
- «Удалить» освобождает место, занятое этой моделью, включая незавершённую загрузку.
- Включение и выключение сохраняют выбор использования модели отдельно от её файлов. Выключение останавливает текущую проверку; скачанное остаётся на диске.
- «Проверить» запускает короткие встроенные примеры на русском, английском и с кодом. История буфера не передаётся модели. После проверки или отмены процесс завершается и освобождает память.

Для моделей на этом этапе нужен Mac с Apple Silicon и macOS 14+. Сеть нужна для загрузки файлов; проверка уже скачанной модели выполняется локально.

## Устройство

`BufferaModels` не зависит от истории и MCP. Он управляет каталогом, состоянием и загрузкой через системный `URLSession`. Файлы принадлежат только Buffera и хранятся в `~/Library/Application Support/Buffera/Models`; общего кеша Hugging Face и дополнительной копии весов нет.

Каждый элемент каталога закреплён за commit репозитория, размером и SHA-256. Загрузка идёт в `.part`; HTTP Range продолжает её с фактического размера файла. Ответ `200` вместо `206` начинает этот файл заново. Некорректный диапазон, размер или контрольная сумма дают ошибку, а не готовую модель. Перенос проверенного файла в готовое состояние выполняется после завершения записи. Поздний ответ отменённой операции не должен восстанавливать удалённую модель.

Менеджер принадлежит `AppDelegate`, поэтому закрытие настроек не отменяет загрузку. При завершении приложения незавершённые операции приостанавливаются. Ошибки модели видны в её карточке и не останавливают захват буфера.

Для запуска используется готовая библиотека [llama.cpp](https://github.com/ggml-org/llama.cpp) с Metal. `BufferaModelProbe` — короткоживущий процесс с фиксированными проверочными заданиями. Это не сетевой сервер: он получает только роль модели и локальный путь, возвращает JSON и завершается. Отдельный процесс позволяет отменить загрузку весов в память и изолировать сбой движка от приложения.

MLX Swift был рассмотрен первым. На момент реализации его стабильный выпуск ещё не включал EmbeddingGemma 2, а сборка Metal требовала полного Xcode. Готовая сборка llama.cpp позволила сохранить macOS 14 и сборку Buffera через Command Line Tools. Последующие этапы должны переиспользовать выбранные файлы моделей и общий слой управления, а не создавать второй загрузчик.

## Воспроизводимая сборка

`scripts/prepare-model-runtime.sh` загружает закреплённый официальный выпуск llama.cpp, проверяет SHA-256, компилирует небольшой probe и помещает нужные библиотеки и лицензию внутрь `.app`. Веса моделей в пакет приложения не входят и при сборке не скачиваются.

Проверки загрузчика: `swift run --disable-sandbox --cache-path .build/cache BufferaModelChecks`. Они используют отдельные временные каталоги и тестовые ответы сети. Результаты проверки настоящих моделей и интерфейса фиксируются в [verification.md](verification.md).
