# Buffera landing

[English](../docs/en/website.md) · **Русский** · [Документация](../docs/README.ru.md)

Самостоятельный статический лендинг на восьми языках: русский, английский, испанский, немецкий, французский, португальский (Бразилия), китайский (упрощённый) и японский. Исходники в `src/`, без внешних UI-библиотек, шрифтов или запросов к истории приложения. Объёмный фирменный знак нарисован CSS; пружина реагирует на указатель и нажатие, учитывает `prefers-reduced-motion` и останавливается вне экрана.

На лендинге и во всей документации подключена Яндекс Метрика `113828609`: Вебвизор, карта кликов, отслеживание ссылок, точный показатель отказов, `ssr` и `ecommerce: "dataLayer"` по предоставленному коду. Общий фрагмент — `scripts/analytics.mjs`, подключение через `renderPage` в `scripts/i18n.mjs`. Нейтральные маршруты с автоматическим выбором языка не запускают JavaScript-счётчик до перенаправления, чтобы не учитывать один переход дважды; `noscript`-пиксель присутствует и на их английских резервных страницах. Метрика относится к публичному сайту и не получает историю из приложения Buffera. Блокировка или ошибка загрузки внешнего скрипта не блокирует интерфейс сайта.

```sh
cd landing
npm run check
npm run build
npm run preview
```

Корневой адрес http://127.0.0.1:4173/ выбирает язык по предпочтениям браузера: первый поддерживаемый язык из `navigator.languages` (`ru`, `en`, `es`, `de`, `fr`, `pt-BR`, `zh-Hans`, `ja`, включая региональные варианты), а если список недоступен — по `navigator.language`. Португальские варианты используют бразильский перевод. Китайский `zh`, `zh-CN`, `zh-SG` и `zh-Hans` выбирает упрощённый перевод; `zh-Hant` и TW/HK/MO без явного Hans пропускаются. Если поддерживаемого языка нет, используется английский. Перенаправление сохраняет query string и hash; отдельного переключателя на странице нет.

Явные адреса `/<язык>/`, например http://127.0.0.1:4173/de/ и http://127.0.0.1:4173/ja/, всегда открывают выбранный язык и не перенаправляют. Сборка создаёт готовый HTML для всех восьми языков и нейтрального адреса. Без JavaScript корень показывает полноценную английскую страницу, а явные языковые адреса сохраняют свой язык. Демо использует только вымышленные примеры, фильтруется и открывает просмотр с клавиатуры; буфер посетителя не читает и не меняет.

`src/index.html` — общий шаблон; весь переводимый текст, включая демо и доступные подписи, хранится в `src/locales/<язык>.json`. `scripts/i18n.mjs` проверяет полноту словарей, подстановки и стабильность идентификаторов демо. `npm run check` также проверяет готовый HTML, метаданные, безопасное встраивание JSON и выполняет корневой скрипт выбора языка в VM с разными настройками браузера. Для публикации нужен результат `npm run build`, а не необработанный шаблон.

Каждая языковая версия получает собственные canonical, hreflang, Open Graph и Twitter Card, включая PNG 1200×630 в `src/og/`. `x-default` указывает на корень, а его статическая английская версия использует canonical `/en/` и английские метаданные, в том числе для просмотра без JavaScript и внешних превью. Сборка публикует только PNG; SVG и `generate.mjs` сохраняют исходники графики. Для повторной генерации нужен `sharp`: `SHARP_MODULE=/path/to/node_modules/sharp node src/og/generate.mjs`. Адрес сайта для метаданных задан в `scripts/i18n.mjs`.

Подпись автора берётся из `page.maker_credit` в языковом JSON; имя `@dqunbp` ведёт в профиль GitHub. Иконки ведут на https://t.me/crypto_and_pug и https://github.com/dqunbp. Ссылка на репозиторий приложения остаётся отдельной.

В последней секции со скачиванием — кнопка добровольной поддержки через Tribute. Адрес задан один раз в `scripts/i18n.mjs`, подписи и подсказка — в языковых JSON. Ссылка открывается в новой вкладке и работает без JavaScript. Объёмная сиреневая кнопка реагирует на наведение и нажатие; уменьшение движения отключает перемещения, клавиатурный фокус остаётся видимым.

В завершающей строке hero, под основной композицией — бейдж создания с GPT Astra в режиме Ultra. Он открывает [официальную страницу GPT-6 Astra](https://openai.com/index/gpt-6-astra/) в новой вкладке и доступен с клавиатуры. Он относится к разработке продукта; встроенные умные функции по-прежнему используют локальные модели. Чёрный знак OpenAI в `src/openai-mark.svg` взят из [Wikimedia Commons](https://commons.wikimedia.org/wiki/File:OpenAI_logo_2025_(symbol).svg); логотип принадлежит OpenAI. Его пропорции и цвет сохранены, оформление находится на окружающем бейдже. [Руководство по знакам OpenAI](https://openai.com/brand/).

При наведении мыши бейдж наклоняется вслед за курсором, логотип и метка Ultra выступают над основанием, а по фону один раз проходит блик. Область наведения и клика мышью выступает на 20 px со всех сторон, без изменения раскладки; она не перекрывает соседнюю стрелку перехода к демо. Координаты считаются по неподвижной обёртке; обновление объединяется в один animation frame. Уход курсора, отмена указателя, скрытие вкладки или изменение настройки движения сбрасывают эффект. Сенсорный указатель и `prefers-reduced-motion` оставляют статичный бейдж; постоянного цикла анимации нет.

Тексты должны соответствовать текущему приложению и README; перед изменением утверждений проверяйте реализацию и её проверки. На странице описываем действия и результат для пользователя; устройство шифрования и ограничения хранения поясняем ниже. Адрес репозитория задан владельцем: https://github.com/dqunbp/buffera. Кнопка скачивания ведёт прямо на `releases/latest/download/Buffera-macOS-arm64.dmg`; имя файла сохраняется между выпусками. Ссылка на исходники ведёт в корень репозитория. В карточке установки указаны Apple Silicon, подпись Developer ID и нотарификация Apple для публичного выпуска 1.0.0; при первом запуске пользователь подтверждает открытие загруженного приложения, если macOS попросит. Этот текст публикуется только после успешной проверки нотарификации релизного артефакта. Поиск по смыслу и встроенный чат требуют Apple Silicon и отдельных моделей. На странице описаны выбор хранения секретов, ручное скрытие и ограничения распознавания. MCP представлен компактной четвёртой карточкой `#mcp` рядом с OCR, очисткой текста и соседними записями: значок MCP, Codex / Claude Code, короткое описание и ссылка на подключение в документации сайта. Все четыре возможности имеют одинаковый визуальный вес. На средних экранах сетка переходит в две колонки, на узких — в список. Отдельной большой секции, примера диалога и дублирующего пункта в раскрывающемся списке нет. Подробности исключения секретов из поиска и доступа агентов описаны только в документации. Экономия батареи относится к фоновой подготовке поиска по смыслу.

Поведение секретов, на которое опираются все локализации:

- В «Настройки → История → Секреты в истории» по умолчанию выбрано «Не сохранять секреты». Альтернатива — «Сохранять секреты зашифрованными». Настройка влияет на новые копирования; ранее сохранённые секреты остаются зашифрованными.
- Секрет определяется по отметкам приложения-источника (`org.nspasteboard.ConcealedType` или `com.agilebits.onepassword`), а не по содержимому пароля. Без отметки запись может сохраниться как обычная. Поэтому страница не обещает автоматически распознавать любые пароли.
- При включённом сохранении содержимое секретов шифруется AES-256-GCM, ключ хранится в Связке ключей macOS. Если ключ недоступен, помеченный секрет не сохраняется открытым. Обычные записи, а также метаданные секретов (например, приложение и дата) остаются без шифрования: это не шифрование всей истории.
- Команда «Скрыть содержимое» для сохранённого текста или ссылки тоже шифрует содержимое и убирает его из поисковых индексов, независимо от режима сохранения новых секретов. В Buffera секрет можно временно раскрыть или скопировать.
- Содержимое секретов исключено из текстового поиска, OCR, поиска по смыслу, контекста встроенного помощника и MCP. MCP не получает ключ и может видеть только безопасные метаданные секретных записей. Доступ к обычной истории через MCP включает пользователь; внешний агент может отправлять прочитанные данные своему сервису.
- Локальная история и встроенные умные функции не требуют передачи содержимого в облако. Это утверждение не распространяется на подключённых внешних агентов.

Подробности поведения и хранения: [руководство приложения](../docs/guide.md) и [архитектура](../docs/architecture.md). Это ссылки внутри основного репозитория; отдельная копия исходников лендинга в Sites не содержит эти файлы.

Основной сайт предназначен для публикации на GitHub Pages: https://buffera.app/. Workflow `../.github/workflows/pages.yml` запускается при изменениях `landing/` или самого workflow в `main`, а также вручную, выполняет `npm run check` и `npm run build`, затем публикует только `landing/dist`. Custom domain `buffera.app` задаётся в настройках Pages репозитория `dqunbp/buffera`; при публикации через Actions файл `CNAME` не требуется. Для этой схемы DNS в Cloudflare должен направлять домен на GitHub Pages в режиме DNS only. Файл `.openai/hosting.json` относится к прежней отдельной публикации Sites, а не к текущему workflow Pages. Перед изменением хостинга проверяйте фактические настройки домена и публикации.

Демо повторяет панель приложения: поиск и булавка, история/избранное, боковые фильтры, действия карточек и крупные изображения. По умолчанию превью открывается в светлой теме. В фильтрах используются иконки Notes, Safari, Screenshot и Terminal из macOS, включённые в статическую сборку. Настройки (шестерёнка) переключают системную, светлую и тёмную тему только внутри демо. Поиск, тип, приложение, период, избранное, соседние записи, скрытие и просмотр работают на четырёх вымышленных записях; все они относятся к сегодняшнему дню. Копирование, Finder и сохранение показывают пояснение и не обращаются к буферу или файлам посетителя. Скрытие в демо лишь меняет отображение вымышленных данных; настоящее шифрование и настройка хранения секретов доступны в установленном приложении. SVG-скриншот кофейни — вымышленный пример.

Под поиском — галочка «Искать также по смыслу» и фирменная кнопка «Спросить», как в приложении. Галочка включает совпадения по подготовленным темам примеров (`keywords`); без неё поиск идёт по тексту и приложению-источнику. Модель в браузере не запускается. «Спросить» открывает подписанный готовый пример поиска адреса в истории буфера обмена. Ответ показывает карточку найденного скриншота, приложение-источник и время копирования; карточка открывает исходную запись. Диалог использует общее окно просмотра, Tab/Shift+Tab, Escape и возврат фокуса. Скрытое содержимое исключается из обоих режимов поиска.

Точечная текстура используется локально: с плавным затуханием за объёмным знаком, в тёмном блоке клавиш и внутри демо. В секции скачивания — отдельный редкий узор из фирменного знака (`brand-pattern.svg`), затухающий к тексту. Остальные текстовые разделы остаются на чистом фоне. Стеклянные элементы используют CSS backdrop-filter с плотной заливкой для браузеров без blur; уменьшение прозрачности и повышенный контраст отключают текстуру и размытие. В приложении панель поиска использует NSGlassEffectView на macOS 26+, а на macOS 14–15 — NSVisualEffectView.

## Документация сайта

Раздел доступен на `/<язык>/docs/` для каждого поддерживаемого языка. В шапке и подвале лендинга есть ссылка «Документация»; карточка MCP ведёт сразу в руководство подключения агентов. Документация сохраняет палитру, системный шрифт и объёмные материалы лендинга. На широких экранах доступны боковая навигация и оглавление статьи; на узких навигация раскрывается по нажатию.

Восемь руководств: `getting-started`, `history`, `search`, `assistant`, `privacy`, `shortcuts`, `agents`, `troubleshooting`. Каждое имеет отдельный статический HTML, canonical, hreflang и локализованные Open Graph / Twitter метаданные с существующими фирменными карточками. `/docs/` и `/docs/<article>/` выбирают язык браузера тем же механизмом, что корень сайта, сохраняя статью, query и hash; без JavaScript показывают английский текст. Явного переключателя языка нет, как и на лендинге. Переходы с лендинга и между статьями сохраняют выбранную языковую версию.

Тексты находятся в `src/locales/docs/<язык>.json`; `scripts/docs.mjs` проверяет полноту переводов, стабильность адресов и якорей, рендерит типизированные блоки (текст, шаги, список, примечание, таблица, код). Новая статья добавляется во все словари с одинаковыми `id` и структурой. Переводы экранируются как текст; HTML в словарях не используется. Данные поиска безопасно встроены в HTML. `src/docs.html`, `src/docs.css` и `src/docs.js` отвечают за шаблон, оформление и улучшения интерфейса.

Поиск выполняется в браузере по заголовкам и полному тексту разделов, без сети и внешних библиотек. `/` или `⌘K` / `Ctrl+K` переводит фокус в поиск; Escape очищает его. Результаты ведут к конкретным разделам. Без JavaScript тексты, ссылки и раскрываемая навигация доступны, поиск и копирование скрыты. Копирование JSON происходит только по нажатию кнопки; при отказе браузера сообщается о возможности скопировать вручную.

Источники для проверки инструкций — README, `docs/mcp.md`, `SecretHistorySettings.swift`, `MCPAccess.swift`, `AppearanceSettings.swift`, `HistoryPanel.swift`, `HistoryResetPreferences.swift` и локализация приложения. Вкладка подключения называется `MCP`; кнопка закрепления находится справа от поля поиска. При изменении поведения приложения обновляйте все языковые версии соответствующей статьи. `npm run check` проверяет переводы, метаданные, редиректы, якоря поиска и безопасность подстановок. Сборка создаёт 90 HTML-страниц: 9 лендингов и 81 страницу документации, включая адреса с автоматическим выбором языка.
