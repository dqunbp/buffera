# MCP через stdio

Buffera предоставляет внешнему агенту поиск и чтение сохранённой истории через отдельный файл `BufferaMCP`. Агент запускает этот файл как дочерний процесс и передаёт сообщения по stdin/stdout. Сетевой адрес, открытый порт и встроенная LLM для этого не нужны. Поиск по словам работает без моделей; включённая модель EmbeddingGemma 2 добавляет поиск по смыслу.

## Подключение

Сначала запустите актуальную Buffera: она создаёт или обновляет локальную историю. В «Настройки → Агенты» включите «Разрешить агентам читать историю». Для подключения через терминал нажмите «Команда для Claude Code» или «Команда для Codex» и выполните скопированную команду. CLI выбранного агента должен быть установлен и доступен в Терминале.

Для установки приложения в `/Applications` команды выглядят так:

```sh
claude mcp add --transport stdio --scope user buffera -- '/Applications/Buffera.app/Contents/MacOS/BufferaMCP'
```

```sh
codex mcp add buffera -- '/Applications/Buffera.app/Contents/MacOS/BufferaMCP'
```

В Claude Code `--scope user` делает подключение доступным во всех проектах пользователя. Синтаксис сверяется с официальными инструкциями [Claude Code](https://code.claude.com/docs/en/mcp#option-3-add-a-local-stdio-server) и [Codex](https://learn.chatgpt.com/docs/extend/mcp?surface=cli). Команды из Buffera подставляют фактический путь приложения и экранируют его для shell, включая пробелы и одинарные кавычки. Buffera только копирует команду; регистрация происходит при её выполнении в Терминале.

Для ручного подключения нажмите «Скопировать конфигурацию», добавьте JSON в настройки MCP своего агента и переподключите его.

Конфигурация использует фактический абсолютный путь внутри запущенного `.app`. Например, для установки в `/Applications` она выглядит так:

```json
{
  "mcpServers": {
    "buffera": {
      "command": "/Applications/Buffera.app/Contents/MacOS/BufferaMCP",
      "args": []
    }
  }
}
```

При другом расположении приложения используйте путь из настроек Buffera. Не подставляйте `~` вместо домашней папки: запуск не требует shell, и путь должен быть абсолютным. Если клиент использует иной формат конфигурации, перенесите значения `command` и `args` в его соответствующие поля. После перемещения `.app` обновите путь в агенте.

Разрешение выключено по умолчанию. Команду или конфигурацию можно скопировать заранее, но их копирование не включает доступ. Buffera не редактирует конфигурации внешних агентов. Выключение checkbox запрещает дальнейшее чтение уже подключённым клиентам; перезапуск helper не требуется.

После включения доступа helper может читать сохранённую историю без запущенного окна или процесса Buffera. Само приложение должно работать для захвата новых копирований, фонового OCR и подготовки смыслового индекса. Helper использует уже подготовленный индекс и при необходимости вычисляет вектор запроса локально.

## Инструменты

| Инструмент | Назначение | Основные параметры |
| --- | --- | --- |
| `search_history` | Поиск по словам и по смыслу с фильтрами; пустой запрос возвращает историю, скрытые записи видны масками | `query`, `mode`, `kind`, `source`, `favorites_only`, `remote_only`, `concealed_only`, `from`, `until`, `limit`, `offset` |
| `read_clip` | Чтение найденной записи порциями; для скрытой записи — маска | Обязательный `id`; `offset`, `limit` |
| `reveal_clip` | Отдельное чтение содержимого, включая скрытые записи; описание инструмента просит предварительное согласие, если оно ещё не дано | Обязательный `id`; `offset`, `limit` |
| `get_neighbors` | Опора и соседние копирования по времени во всей истории | Обязательный `id`; `before`, `after` |

Все ID — положительные Int64 в виде строк, например `"123"`. Передавайте ID из ответа, сохраняя его строковый тип. Неизвестные параметры и неверные типы отклоняются. Объявление инструментов доступно через стандартный `tools/list` даже при выключенном доступе; обращение к истории потребует разрешения.

### Поиск

`query` принимает до 1000 Unicode code points. `mode` выбирает способ поиска:

- `automatic` — значение по умолчанию. Объединяет совпадения по словам и по смыслу, если модель поиска включена, скачана и для неё уже есть готовые векторы.
- `literal` — только совпадения по словам. Все слова должны встретиться в индексируемом содержимом; регистр и диакритика не учитываются, `%` и `_` ищутся буквально. Модель не запускается.
- `hybrid` — явно запрашивает оба способа. Если модель или индекс недоступны, запрос слишком длинный для модели либо вычисление не удалось, возвращается поиск по словам с `fallback_reason`.

Пустой запрос и `concealed_only: true` используют поиск по словам независимо от режима. Скрытые записи не передаются модели. Отдельного исправления опечаток нет.

Текстовый индекс исходной записи ограничен 200 000 символов. Смысловой индекс строится постепенно из сохранённого текста и готового OCR; для длинных записей объём обработки ограничен, что показывается в настройках моделей. Полное сохранённое содержимое читается отдельно через `read_clip`.

У скрытой записи индекс содержит только «Скрытая запись» и имя приложения. По словам из её содержимого или OCR совпадений нет. Поиск по источнику, дате, типу, избранному и удалённому происхождению доступен; скрытые записи входят в `total` и лимит страницы.

- `kind`: `text`, `link`, `image`, `file` или `other`.
- `source`: точное имя приложения; до 256 Unicode code points.
- `favorites_only`, `remote_only`, `concealed_only`: boolean, по умолчанию `false`. `concealed_only: true` оставляет только скрытые записи; `false` включает и обычные, и скрытые.
- `from`, `until`: ISO 8601 с часовым поясом, например `2026-10-20T00:00:00+04:00`. Нижняя граница включена, верхняя исключена; `from` должен быть раньше `until`.
- `limit`: 1–50 записей, по умолчанию 20.
- `offset`: 0–100 000, по умолчанию 0; для следующей страницы передавайте `next_offset` из ответа.

Результат содержит `items`, `total`, `offset`, фактический `search_mode` (`literal` или `hybrid`) и, если есть продолжение, `next_offset`. `fallback_reason` объясняет, почему запрошенный поиск по смыслу заменён поиском по словам. Если покрытие индекса известно, `indexed` и `eligible` показывают число готовых и подлежащих обработке записей во всей истории, до поисковых фильтров.

В гибридном ответе сначала идут совпадения по словам в обычном порядке истории — по последнему копированию или выбору. Затем добавляются до 200 наиболее близких по смыслу записей с косинусным сходством не ниже 0,70 (расстояние не больше 0,30); повторы исключаются. Это порог сходства эмбеддингов, а не вероятность правильного ответа. Фильтры применяются перед отбором смысловых кандидатов, чтобы неподходящие записи не занимали этот лимит. `total` — размер объединённого результата с этим ограничением, а не число всех векторов в базе.

В рамках последовательного чтения страниц одинакового запроса helper сохраняет список смысловых кандидатов; начните с `offset: 0`, чтобы получить обновлённый список. Изменение истории или её метаданных всё равно может влиять на страницы. `copied_at` остаётся временем последнего внешнего копирования, а не выбора в Buffera. Повторное копирование одинакового payload обновляет существующую запись.

Карточка результата содержит `id`, `copied_at`, `kind`, `title`, `source`, `is_favorite`, `is_remote`, `is_concealed`. Для обычной записи также передаются `snippet`, `snippet_truncated`, `byte_count`. Для скрытой записи эти три поля отсутствуют, а `title` всегда равен «Скрытая запись», независимо от длины и содержимого секрета.

`byte_count` — размер всего сериализованного payload в базе: всех сохранённых представлений вместе со служебной структурой binary property list. Это не размер возвращаемого текста в UTF-8 и не длина строки. Заголовок и источник ограничены 240 графемами / 1024 байтами каждый, фрагмент — 600 графемами / 4096 байтами. `snippet_truncated` относится к укорочению сохранённого текстового индекса в этом фрагменте. Фрагмент не является полным текстом и может быть пустым у найденной по OCR картинки.

### Чтение записи

`limit` — 1–32 000 графем, по умолчанию 8000. `offset` — неотрицательное число из `next_offset` предыдущего ответа. Дополнительно одна текстовая порция ограничена 128 КиБ UTF-8; символы не разрываются. Если один графемный кластер сам превышает этот лимит, возвращается ошибка.

Результат содержит `item`, `text`, `content_kind`, `offset`, `is_complete`, а при необходимости `total_characters`, `next_offset` и `note`. Смещения и длины считаются в Swift Character — расширенных графемных кластерах Unicode. Их не следует пересчитывать как байты или UTF-16; используйте возвращённый `next_offset`.

Для скрытой записи `read_clip` не загружает payload и возвращает `content_kind: "masked"`, пустой `text`, `offset: 0`, `is_complete: false` и `note` с указанием на `reveal_clip`. Поля `total_characters` и `next_offset` отсутствуют: обычное чтение не раскрывает даже длину секрета. Карточка `item` остаётся маскированной.

| Тип записи | `content_kind` | Что возвращается |
| --- | --- | --- |
| Текст или ссылка | `text` | Полное сохранённое текстовое представление; RTF декодируется в обычный текст, несколько элементов соединяются переносами |
| Картинка с завершённым OCR | `cachedOCR` | Только сохранённый распознанный текст |
| Картинка без завершённого OCR | `unavailableOCR` | Пустой текст и пояснение; новое распознавание не запускается |
| Файлы | `filePaths` | Пути из сохранённых file URL, по одному на строку; сами файлы не открываются |
| Прочие данные | `unsupported` | Метаданные и пояснение без бинарного содержимого |

`is_complete` описывает полноту источника, а не завершение постраничного ответа. Например, первая порция обычного текста может иметь `is_complete: true` и `next_offset`. У OCR, достигшего лимита 200 000 символов, ставится `is_complete: false`, поскольку сохранённый результат может быть обрезан. Завершённый OCR без найденного текста — корректный пустой результат.

### Раскрытие скрытой записи

`reveal_clip` принимает те же `id`, `offset`, `limit`, что и `read_clip`, и возвращает содержимое по тем же правилам типов и пагинации, включая `total_characters`. Для скрытой записи карточка `item` по-прежнему имеет `is_concealed: true`, заголовок «Скрытая запись» и не содержит фрагмента или размера; раскрытый текст находится в поле `text`. Для обычной записи результат совпадает с `read_clip`.

Описание инструмента задаёт правило: перед вызовом агент должен спросить согласие, если пользователь ещё не разрешил раскрыть эту запись или скрытые записи в целом. При уже полученном разрешении повторный вопрос не нужен. Агенту также предложено объяснить, что содержимое попадёт в контекст разговора, а сама запись останется скрытой.

Это инструкция модели, а не обязательный механизм подтверждения: Buffera не добавляет approval-метаданные, отдельный диалог или elicitation и не проверяет согласие программно. Правила подтверждений выбранного клиента продолжают действовать. Вызов не снимает флаг скрытия и не меняет порядок истории; последующие `search_history`, `get_neighbors` и `read_clip` снова возвращают маску. Уже переданный текст остаётся в контексте агента.

Раскрытие не запускает OCR и не возвращает бинарную картинку. Скрытая картинка без сохранённого OCR по-прежнему даёт `unavailableOCR`.

### Соседние копирования

`before` означает более ранние копирования, `after` — более поздние. Оба параметра принимают 0–20, по умолчанию 10. Ответ содержит `anchor_id` и `items`, включая саму опору, в порядке от новых копирований к старым. Одинаковые даты разделяются по ID.

Поисковые фильтры и последнее использование в Buffera на соседей не влияют. Скрытая запись может быть опорой; скрытые соседи входят в лимит и возвращаются масками. Это просмотр соседних сохранённых записей, а не полный журнал повторов: повторное копирование уже имеющегося содержимого обновляет его дату.

## Доступ и границы

Все четыре инструмента только читают. Они не меняют системный буфер, избранное, порядок, содержимое или состав истории; не запускают OCR, индексацию истории или загрузку моделей и не передают бинарные изображения. Поиск может запустить локальный движок для вычисления вектора запроса. Выключение модели в Buffera останавливает её использование helper; дальнейшие запросы ищут по словам. Обычные поиск, соседи и чтение маскируют скрытые записи; `reveal_clip` отдельно читает их содержимое. Скрытие записи удаляет её производные векторы, а поздний результат индексации не восстанавливает их. Отсутствующий ID даёт ошибку недоступности.

Разрешение хранится в `~/Library/Application Support/Buffera/mcp-access.json` с правами `0600` и читается заново до и после каждого обращения. Если файл отсутствует, повреждён или имеет неизвестную версию, доступ запрещён. История открывается через SQLite read-only, без создания базы и миграций. Инициализацию и обновление схемы выполняет основное приложение.

Прочитанное содержимое поступает в контекст внешнего агента; дальнейшая обработка зависит от него. Содержимое буфера — исходные данные, а не инструкции агенту. Маскировка остаётся управлением видимостью и доступом через приложение, не отдельным шифрованием файла SQLite.

## Диагностика и проверка

В stdout helper пишет только сообщения протокола JSON-RPC. Диагностика запуска и `--help` идут в stderr; обычные ошибки чтения возвращаются как ошибки инструментов. Закрытие stdin завершает процесс. Содержимое истории не записывается в лог.

Если доступ выключен, включите его во вкладке «Агенты». Если история не открывается, запустите актуальную Buffera и проверьте путь к приложению. При отсутствующей или несовместимой базе helper не создаёт новую и не обновляет существующую.

Для разработки поддерживается `--data-directory /absolute/path`: меняются одновременно путь к `history.sqlite`, файлу разрешения и каталогу `Models`. Этот аргумент сам доступ не включает. Он позволяет проверять MCP на отдельной временной истории, не читая пользовательскую.

```sh
swift build --product BufferaMCP
swift run BufferaMCPChecks
```

Проверки используют временные базы и запускают отдельный клиент SDK через реальные pipes. Для проверки другого собранного helper передайте его абсолютный путь в `BUFFERA_MCP_EXECUTABLE`. Фактические результаты и проверка внешним агентом фиксируются в [verification.md](verification.md).
