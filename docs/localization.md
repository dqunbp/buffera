# Локализация

`BufferaLocalization` — общий Foundation-модуль для интерфейса, моделей, поиска,
чата и ошибок. Переводы находятся только в
`Sources/BufferaLocalization/Resources/{ru,en}.lproj/Localizable.strings`.
В `Package.swift` объявлены `defaultLocalization` и обработка ресурсов SwiftPM.
`scripts/build-app.sh` переносит ресурсный bundle в `Contents/Resources`,
объявляет оба языка в Info.plist и подписывает готовое приложение.
Перед копированием ресурсный bundle заменяется целиком: смешение плоской структуры SwiftPM и старой `Contents/Resources` может заставить Foundation загружать устаревшие переводы.
`L10n.resources` явно загружает этот bundle из пакета приложения, включая прямой запуск вложенного MCP-бинарника. В установленном `.app` нельзя полагаться на сгенерированный `Bundle.module`: он ищет bundle в корне `.app`, а затем по абсолютному пути сборки, что может вызвать запрос доступа к «Документам». Для обычных SwiftPM-бинарников остаётся `Bundle.module`.

## Выбор языка

`LanguagePreference` хранит три варианта; отсутствие или некорректное значение
`interfaceLanguage` в UserDefaults означает системный режим. Он просматривает
`Locale.preferredLanguages` по порядку, поддерживает региональные варианты и
использует английский, если ни один язык не поддерживается.

Явный выбор сохраняет также `AppleLanguages` в домене приложения, чтобы
системные панели при следующем запуске использовали тот же язык. Возврат
к системному режиму удаляет оба переопределения. Глобальные настройки macOS
не изменяются.

`L10n` фиксирует язык на время запуска. Смена выбора не пересоздаёт окна,
не прерывает генерацию ответа и не смешивает новые подписи со старыми
фоновыми сообщениями. Если выбранная настройка отличается от настройки при запуске,
в настройках появляются сообщение о необходимости перезапуска и кнопка
«Перезапустить Buffera». Возврат к исходному выбору убирает сообщение;
закрытие окна настроек не сбрасывает ожидающее изменение.

Кнопка использует обычное завершение приложения и `AppRelaunch`: вспомогательный
процесс ждёт выхода текущего PID, затем открывает тот же `.app` через macOS
с аргументом `--show-settings`. Это сохраняет защиту от двух одновременно
работающих экземпляров и возвращает настройки на новом языке. Путь приложения
передаётся отдельным аргументом, а не вставляется в shell-код. Если подготовка
перезапуска не удалась, приложение остаётся открытым и показывает ошибку.
Регион для чисел и дат берётся из пользовательской локали, язык — из
выбора интерфейса; часы и порядок компонентов дат используют локальные шаблоны.

## Строки и границы

Пользовательские литералы передаются через `L10n.text`. Интерполяция выделяет
значения в отдельные аргументы, а ключ содержит позиционные `%1$@`, `%2$@` и т. д.
Это позволяет менять порядок слов, сохраняет текст аргументов без перевода
и не интерпретирует находящиеся внутри них проценты как формат.
Проценты в самом литерале экранируются. Ключом служит исходный русский шаблон.
При отсутствии перевода используется английский, затем исходный шаблон.
Счётчики сформулированы с подписью перед числом, чтобы не требовать склонения
существительного после произвольного числа.

`L10n.diagnostic` применяется только к известным сообщениям нативных движков
и сохранённым ошибкам: точное соответствие в каталоге позволяет показать
их на текущем языке. Неизвестные технические подробности остаются исходными.
К содержимому буфера и ответам модели этот метод применять нельзя.

Служебные сохранённые заголовки, `HistoryStore.concealedTitle` и локаль
`SearchFilter.normalize` остаются стабильными. `ClipSummary.displayTitle`
переводит стандартные подписи при показе, не обновляя базу. Пользовательские
названия, текст, пути, идентификаторы, настройки моделей, протокол MCP
и инструкции помощника от языка интерфейса не зависят.

## Проверки

```sh
swift run --disable-sandbox --cache-path "$PWD/.build/cache" BufferaLocalizationChecks
swift build --disable-sandbox --product Buffera
.build/debug/Buffera --localization-ui-smoke-test -interfaceLanguage ru -AppleLanguages '(ru)'
.build/debug/Buffera --localization-ui-smoke-test -interfaceLanguage en -AppleLanguages '(en)'
.build/debug/Buffera --updates-ui-smoke-test -interfaceLanguage ru -AppleLanguages '(ru)'
.build/debug/Buffera --updates-ui-smoke-test -interfaceLanguage en -AppleLanguages '(en)'
zsh scripts/check-history-panel.sh
```

Проверки локализации сверяют все ключи и параметры двух каталогов, выбор
региональных языков и fallback, сохранение и очистку настроек, экранирование,
неизменность пользовательского текста и метаданных. UI-проверка использует
реальные элементы окна настроек с отдельным доменом UserDefaults и временной
папкой; пользовательская история и буфер не затрагиваются. Отдельный скрипт
проверяет существующие взаимодействия панели на обоих языках.

Проверка обновлений использует подставной релиз и изолированные настройки: проверяет точку на значке, пропуск версии, ошибки сети и размещение раздела «Обновления». Сеть и браузер не открываются. Логику GitHub-клиента проверяет `swift run BufferaUpdateChecks`; флаг `--live` дополнительно выполняет реальный публичный запрос.

Для других самостоятельных `swiftc`-проверок, компилирующих исходники приложения,
теперь также требуется модуль `BufferaLocalization`, его библиотека и ресурсный
bundle рядом с исполняемым файлом. Пример сборки — `scripts/check-history-panel.sh`.

Финальный `.app` проверяется после переноса за пределы checkout: основной
бинарник и `BufferaMCP --help` должны находить переводы внутри пакета.
`zsh scripts/check-packaged-localization.sh` проверяет RU/EN в отдельном пакете из `/private/tmp` с запретом чтения исходного checkout и каталога сборки через macOS Sandbox.

Если файловый провайдер повторно добавляет FinderInfo и мешает подписи
ресурсного bundle уже внутри SwiftPM, задайте каталог сборки вне синхронизации:
`BUFFERA_BUILD_PATH=/private/tmp/buffera-build zsh scripts/build-app.sh --disable-sandbox`.
Тот же параметр поддерживает скрипт проверок панели. При обычном `swift build`
ему соответствует `--scratch-path /private/tmp/buffera-build`.
