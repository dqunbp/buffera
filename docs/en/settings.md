# Application settings

Settings use a compact sidebar with navigation aligned at the top: General, AI, Appearance, History, Shortcuts, MCP, and Updates. Icons and labels have inset spacing. Appearance and history options are grouped into cards; AI brings together semantic search and the assistant. Existing actions and model checks are retained.

At the top of AI settings, a large green shield accompanies an explanation: “All models run locally. Your clipboard history is never sent anywhere.”. This applies to built-in AI features; separately authorized MCP access exposes history to connected agents.

General includes:

- **Interface language** offers System or one of the eight supported languages. Changes take effect after restarting Buffera; theme remains in Appearance.
- **Launch at login** registers the main application through `SMAppService.mainApp`. Settings read the actual macOS status when opened and when the application becomes active. Pending approval shows a mixed checkbox, explanation, and a link to system settings. If macOS cannot find the service (`.notFound`), a neutral “Could not determine launch-at-login status” message appears without assuming the app is not installed; the checkbox remains available. Errors while changing registration restore the actual checkbox state and appear inline. Registration changes only on user action; login launches prepare capture and indexing without opening history.
- **Show menu bar icon** defaults to enabled. The `showMenuBarIcon` preference persists and changes the existing `NSStatusItem` visibility. Background update checks continue, and update details remain accessible in settings. Reopening Buffera with the icon hidden opens settings; the history shortcut and settings button in history remain available.
- **Version and build** come from `Sources/BufferaCore/AppVersion.swift`; the text can be selected and copied.
- **Report an issue** opens `https://github.com/dqunbp/buffera/issues/new` in the browser. The draft contains fields for the problem, expected behavior, and reproduction steps, plus the Buffera version/build, macOS version, and executable architecture. It opens only on click; the user edits and submits the issue. History, logs, paths, user names, and device identifiers are not collected.

History offers limits of 10, 100, 500, 1,000, 5,000, 10,000, 50,000, and 100,000 ordinary clips. The default remains 50,000; favorites do not count toward the limit. The setup wizard uses the same choices. A reduced limit takes effect after the next copy.

**Save temporary clips** is in the History storage card and is off by default. It also saves clips that apps mark as temporary or automatically generated, for example during dictation and automatic text insertion. It applies to `TransientType` and `AutoGeneratedType` markers. If a clip is also marked confidential, Save secrets encrypted must be enabled as well; its content stays encrypted. Changes apply to new copies and do not delete saved clips.

The **Reset window state** checkbox enables two modes: **Immediately after closing** and **After the specified number of minutes** (1–1,440). In the first mode, the minute field is disabled; the selected delay is retained when returning to the second mode. Reset after one minute remains enabled by default. The interface explains: “Automatically reset the interface to its default state on the next opening (clear the search and filters, leave Favorites).” Reset does not delete saved clips or favorites. Immediate mode resets state before background preparation so the next opening can reuse prepared history; an open window is not reset.

In Shortcuts, **Reset shortcuts** restores `⌘⌥V` / `⌘⌥C`; its behavior is unchanged.

Implementation: `AppearanceSettings.swift`, `SettingsNavigation.swift`, `GeneralSettingsView.swift`, `AppPreferences.swift`, `IssueReport.swift`, `SupportBuffera.swift`, `TemporaryHistorySettings.swift`, `ClipboardService.swift`, with wiring in `AppDelegate.swift`.

Verification: `--localization-ui-smoke-test` checks the new controls and light/dark snapshots in all eight languages, visibility persistence, and login errors/approval using an injected service. Temporary capture checks cover the default, persistence after reopening, and independence from the secrets mode. `--smoke-test` exercises combinations of temporary and confidentiality markers and preferences on a separate pasteboard, including rejection before reading excluded content. Tests do not open a browser or change system registration. Existing `--shortcuts-ui-smoke-test`, `--features-ui-smoke-test`, and `--updates-ui-smoke-test` check navigation and existing actions. Synthetic checks do not establish that the installed app starts after an actual macOS logout/login.
